# 2.6 Form Requests

## Overview

A **Form Request** is a custom Laravel request class used to handle:

* Request validation
* Authorization
* Custom validation messages
* Validation attributes

It keeps controllers clean by moving validation logic into a separate class.

---

## Creating a Form Request

Use Artisan:

```bash
php artisan make:request StoreUserRequest
```

Laravel creates:

```text
app/Http/Requests/StoreUserRequest.php
```

---

## Basic Form Request

```php
<?php

namespace App\Http\Requests;
use Illuminate\Foundation\Http\FormRequest;

class StoreUserRequest extends FormRequest
{
    public function authorize(): bool
    {
        return true;
    }

    public function rules(): array
    {
        return [
            'name' => ['required', 'string', 'max:100'],
            'email' => ['required', 'email'],
            'password' => ['required', 'min:8'],
        ];
    }
}
```

### `authorize()`

Determines whether the current user is allowed to make the request.

```php
public function authorize(): bool
{
    return true;
}
```

If it returns `false`, Laravel rejects the request before the controller runs.

### `rules()`

Defines the validation rules:

```php
public function rules(): array
{
    return [
        'name' => ['required', 'string'],
        'email' => ['required', 'email'],
    ];
}
```

---

## Using Form Request in Controller

Instead of:

```php
public function store(Request $request)
{
    $data = $request->validate([
        'name' => 'required|string',
        'email' => 'required|email',
    ]);

    // ...
}
```

Use the Form Request:

```php
use App\Http\Requests\StoreUserRequest;

public function store(StoreUserRequest $request)
{
    $data = $request->validated();

    // Create user
}
```

Laravel automatically validates the request **before the controller method executes**.

---

## Request Flow

```text
HTTP Request
    ↓
StoreUserRequest
    ↓
authorize()
    ↓
rules()
    ↓
Validation
    ↓
Controller
    ↓
Business Logic
```

If authorization or validation fails, the controller is not executed normally.

---

## Getting Validated Data

Use:

```php
$data = $request->validated();
```

Example:

```php
public function store(StoreUserRequest $request)
{
    $data = $request->validated();

    User::create($data);
}
```

You can also retrieve a specific validated value:

```php
$email = $request->validated('email');
```

---

## Custom Validation Messages

Define custom messages using `messages()`:

```php
public function messages(): array
{
    return [
        'name.required' => 'Please enter your name.',
        'email.required' => 'Email address is required.',
        'email.email' => 'Please enter a valid email address.',
    ];
}
```

---

## Custom Attribute Names

You can make validation messages more readable using `attributes()`:

```php
public function attributes(): array
{
    return [
        'email' => 'email address',
        'dob' => 'date of birth',
    ];
}
```

For example, Laravel can display:

```text
The email address field is required.
```

instead of:

```text
The email field is required.
```

## Authorization Example

Suppose only administrators can create users:

```php
public function authorize(): bool
{
    return auth()->user()?->is_admin === true;
}
```

The request is rejected if the user is not authorized.

Authorization can also use route parameters or other request information when required.

---

## Form Request with Business Validation

Example:

```php
class StoreOrderRequest extends FormRequest
{
    public function authorize(): bool
    {
        return auth()->check();
    }

    public function rules(): array
    {
        return [
            'product_id' => ['required', 'integer', 'exists:products,id'],
            'quantity' => ['required', 'integer', 'min:1'],
            'email' => ['required', 'email'],
        ];
    }
}
```

Controller:

```php
public function store(StoreOrderRequest $request)
{
    $order = $this->orderService->create(
        $request->validated()
    );

    return response()->json($order);
}
```

The controller now focuses on handling the request instead of containing validation rules.

---

## Form Request vs `$request->validate()`

### `$request->validate()`

Good for simple validation:

```php
public function store(Request $request)
{
    $data = $request->validate([
        'name' => 'required|string',
        'email' => 'required|email',
    ]);
}
```

### Form Request

Better when validation becomes larger or needs authorization/custom messages:

```php
public function store(StoreUserRequest $request)
{
    $data = $request->validated();
}
```

---

## Important Methods

| Method         | Purpose                                   |
| -------------- | ----------------------------------------- |
| `authorize()`  | Determines whether the request is allowed |
| `rules()`      | Defines validation rules                  |
| `validated()`  | Returns validated input                   |
| `messages()`   | Defines custom validation messages        |
| `attributes()` | Defines custom attribute names            |

---

## Best Practice

Keep request-specific validation inside a Form Request:

```text
Controller
    ↓
Handles request
    ↓
Service
    ↓
Business logic
```

Instead of putting everything inside the controller:

```text
Controller
    ├── Validation
    ├── Authorization
    ├── Business Logic
    ├── Database Logic
    └── Response
```

For larger applications, Form Requests help keep responsibilities separated.

---

## Interview Point

**Q: What is a Form Request in Laravel?**

**Answer:**
A Form Request is a custom Laravel request class that encapsulates validation and authorization logic for a specific type of HTTP request.

**Q: Why use Form Requests?**

**Answer:**
They keep controllers clean and allow validation, authorization, and custom validation messages to be organized in a dedicated class.

**Q: What is the difference between `rules()` and `authorize()`?**

```text
rules()
   ↓
Checks whether input is valid

authorize()
   ↓
Checks whether the user is allowed
```

**Remember:**

```text
Form Request
    ├── authorize()
    ├── rules()
    ├── messages()
    └── attributes()
```
