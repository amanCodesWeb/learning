# 2.3 Single Action (Invokable) Controllers

## Overview

A **Single Action Controller** is a controller designed to handle **only one action**.

Instead of defining multiple methods like `index()`, `store()`, `update()`, etc., the controller uses one `__invoke()` method.

It is useful when a controller has **one clear responsibility**.

---

## Creating an Invokable Controller

Use Artisan:

```bash
php artisan make:controller ProcessPaymentController --invokable
```

Laravel creates:

```php
app/Http/Controllers/ProcessPaymentController.php
```

Example:

```php
<?php

namespace App\Http\Controllers;
use Illuminate\Http\Request;

class ProcessPaymentController extends Controller
{
    public function __invoke(Request $request)
    {
        return "Payment processed";
    }
}
```

---

## Route to an Invokable Controller

Because the controller has only one action, you don't need to specify a method:

```php
use App\Http\Controllers\ProcessPaymentController;

Route::post('/payment', ProcessPaymentController::class);
```

When this route is called, Laravel automatically executes:

```php
__invoke()
```

Flow:

```text
POST /payment
    ↓
ProcessPaymentController
    ↓
__invoke()
    ↓
Payment processed
```

---

## Example with Business Logic

```php
class SendInvoiceController extends Controller
{
    public function __invoke($orderId)
    {
        // Find order
        // Generate invoice
        // Send email

        return "Invoice sent";
    }
}
```

Route:

```php
Route::post('/orders/{orderId}/invoice', SendInvoiceController::class);
```

---

## Why Use Single Action Controllers?

Use them when an endpoint represents **one specific operation**.

Examples:

```text
ProcessPayment
SendInvoice
ExportOrders
GenerateReport
CreateSubscription
CancelSubscription
SendNotification
```

This keeps controllers small and focused.

---

## Normal vs Single Action Controller

### Normal Controller

```php
class OrderController extends Controller
{
    public function index() {}

    public function store() {}

    public function show($id) {}

    public function update($id) {}

    public function destroy($id) {}
}
```

Route:

```php
Route::get('/orders', [OrderController::class, 'index']);
```

### Single Action Controller

```php
class ExportOrdersController extends Controller
{
    public function __invoke()
    {
        return "Orders exported";
    }
}
```

Route:

```php
Route::get('/orders/export', ExportOrdersController::class);
```

---

## `__invoke()` Method

`__invoke()` is a PHP **magic method**.

When an object is called like a function:

```php
$controller();
```

PHP automatically calls:

```php
$controller->__invoke();
```

Laravel uses this behavior for invokable controllers.

---

## Dependency Injection

You can inject dependencies normally:

```php
class ProcessPaymentController extends Controller
{
    public function __invoke(
        PaymentService $paymentService,
        Request $request
    ) {
        $paymentService->process($request->all());

        return "Payment processed";
    }
}
```

Laravel's service container resolves the dependencies automatically.

---

## When to Use

Use a Single Action Controller when:

* The controller has **one responsibility**.
* The endpoint performs a specific operation.
* The action does not naturally belong to a large CRUD controller.
* You want small, focused controllers.

Do not create an invokable controller just because the code is short. Use it when the **single-action responsibility makes the code clearer**.

---

## Interview Point

**Q: What is an Invokable Controller in Laravel?**

**Answer:**
An Invokable Controller is a controller that contains a single `__invoke()` method and is designed to handle one action. It can be registered directly in a route without specifying a controller method.

```php
Route::post('/payment', ProcessPaymentController::class);
```

Laravel automatically calls:

```php
__invoke()
```

**Remember:**

```text
Normal Controller
Controller → Method

Invokable Controller
Controller → __invoke()
```
