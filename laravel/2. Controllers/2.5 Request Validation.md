# 2.5 Request Validation

## Overview

**Request Validation** checks whether incoming user data is valid before processing it.

Laravel provides built-in validation for:

* Required fields
* Strings and numbers
* Email addresses
* Passwords
* File uploads
* Dates
* Unique values
* Relationships
* Custom rules

---

## Basic Validation

Laravel provides the `validate()` method on the request:

```php
public function store(Request $request)
{
    $validated = $request->validate([
        'name' => 'required|string|max:100',
        'email' => 'required|email',
        'age' => 'required|integer|min:18',
    ]);

    // Use validated data
}
```

If validation fails, Laravel automatically redirects back and provides validation errors.

If validation succeeds, `$validated` contains only the validated data.

---

## Common Validation Rules

```php
[
    'name' => 'required|string|max:100',
    'email' => 'required|email',
    'age' => 'integer|min:18|max:100',
    'password' => 'required|min:8|confirmed',
    'status' => 'required|in:active,inactive',
]
```

Common rules:

| Rule        | Purpose                                   |
| ----------- | ----------------------------------------- |
| `required`  | Field must be present                     |
| `nullable`  | Field may be null                         |
| `string`    | Must be a string                          |
| `integer`   | Must be an integer                        |
| `numeric`   | Must be numeric                           |
| `email`     | Must be a valid email                     |
| `min`       | Minimum value/length                      |
| `max`       | Maximum value/length                      |
| `in`        | Value must be one of the given values     |
| `unique`    | Value must not already exist              |
| `exists`    | Value must exist in a database table      |
| `confirmed` | Requires a matching `_confirmation` field |

---

## Validation with Arrays

Rules can be written as arrays:

```php
$validated = $request->validate([
    'name' => ['required', 'string', 'max:100'],
    'email' => ['required', 'email'],
    'age' => ['required', 'integer', 'min:18'],
]);
```

This is useful when using multiple or complex rules.

---

## Validation Errors

Laravel automatically handles validation errors.

For example:

```php
$request->validate([
    'email' => 'required|email',
]);
```

If the email is invalid, Laravel returns a validation error instead of continuing with the controller logic.

In Blade:

```php
@error('email')
    <p>{{ $message }}</p>
@enderror
```

You can also access all errors:

```php
$errors->all()
```

## Form Request Validation

For larger forms, Laravel provides **Form Request classes**.

Create one:

```bash
php artisan make:request StoreOrderRequest
```

Laravel creates:

```text
app/Http/Requests/StoreOrderRequest.php
```

Example:

```php
class StoreOrderRequest extends FormRequest
{
    public function rules(): array
    {
        return [
            'product_id' => ['required', 'integer'],
            'quantity' => ['required', 'integer', 'min:1'],
            'email' => ['required', 'email'],
        ];
    }
}
```

Use it in the controller:

```php
public function store(StoreOrderRequest $request)
{
    $data = $request->validated();

    // Create order
}
```

Flow:

```text
Request
   ↓
StoreOrderRequest
   ↓
Validation
   ↓
Controller
   ↓
Business Logic
```

## Authorization in Form Requests

A Form Request can also control whether the user is allowed to perform the action.

```php
public function authorize(): bool
{
    return auth()->check();
}
```

If `false` is returned, Laravel rejects the request before the controller method runs.

---

## Custom Validation Messages

You can customize messages in a Form Request:

```php
public function messages(): array
{
    return [
        'email.required' => 'Email address is required.',
        'email.email' => 'Please provide a valid email address.',
    ];
}
```

## Conditional Validation

Sometimes a field is required only under certain conditions.

Example:

```php
$validated = $request->validate([
    'payment_method' => 'required|in:card,cash',
    'card_number' => 'required_if:payment_method,card',
]);
```

`card_number` is required only when:

```text
payment_method = card
```

---

## Validation vs Sanitization

Validation checks whether data is acceptable.

```text
Validation
"Is this data valid?"
```

Sanitization transforms or cleans data.

```text
Sanitization
"Can this data be cleaned/normalized?"
```

Laravel validation does not mean that every input should automatically be trusted or used directly.

---

## Best Practice

Validate data **before** passing it to business logic:

```php
public function store(Request $request)
{
    $data = $request->validate([
        'name' => 'required|string',
        'email' => 'required|email',
    ]);

    $this->orderService->create($data);
}
```

For complex forms, prefer a **Form Request**:

```php
public function store(StoreOrderRequest $request)
{
    $this->orderService->create(
        $request->validated()
    );
}
```

This keeps controllers cleaner and moves validation into its own class.

## Interview Point

**Q: What is request validation in Laravel?**

**Answer:**
Request validation checks incoming request data against defined rules before the application processes it.

**Q: What is a Form Request?**

**Answer:**
A Form Request is a custom Laravel request class that encapsulates validation rules and authorization logic for a specific request.

**Q: Difference between `validate()` and `validated()`?**

```php
$request->validate([...]);
```
Runs validation and returns the validated data.

```php
$request->validated();
```
Retrieves the already validated data from a Form Request.

**Remember:**

```text
User Input
    ↓
Validation
    ↓
Validated Data
    ↓
Controller / Service
    ↓
Database
```
