# 2.10 Response Macros

## Overview

A **Response Macro** allows you to define a custom method on Laravel's response factory that can be reused throughout your application.

Instead of repeatedly writing the same response structure:

```php
return response()->json([
    'success' => true,
    'message' => 'Success',
    'data' => $data,
]);
```

you can create a custom macro:

```php
return response()->success($data);
```

Response macros are useful when an application needs **reusable response logic or a consistent API response format**.

---

## Creating a Response Macro

Response macros are commonly registered in a service provider.

Example:

```php
use Illuminate\Support\Facades\Response;

public function boot(): void
{
    Response::macro('success', function ($data, $message = 'Success') {
        return Response::json([
            'success' => true,
            'message' => $message,
            'data' => $data,
        ]);
    });
}
```

After registering the macro, you can use:

```php
return response()->success($user);
```

---

## Using a Macro with a Custom Message

```php
return response()->success(
    $user,
    'User retrieved successfully'
);
```

Response:

```json
{
    "success": true,
    "message": "User retrieved successfully",
    "data": {
        "id": 1,
        "name": "Aman"
    }
}
```

---

## Adding a Status Code

A macro can also accept a status code:

```php
Response::macro('success', function (
    $data,
    $message = 'Success',
    $status = 200
) {
    return Response::json([
        'success' => true,
        'message' => $message,
        'data' => $data,
    ], $status);
});
```

Usage:

```php
return response()->success(
    $user,
    'User created successfully',
    201
);
```

---

## Creating an Error Macro

You can create another macro for errors:

```php
Response::macro('error', function (
    $message,
    $status = 400,
    $errors = []
) {
    return Response::json([
        'success' => false,
        'message' => $message,
        'errors' => $errors,
    ], $status);
});
```

Usage:

```php
return response()->error(
    'User not found',
    404
);
```

Response:

```json
{
    "success": false,
    "message": "User not found",
    "errors": []
}
```

---

## Where to Register Macros

Macros can be registered in a **service provider**, typically in the `boot()` method.

Example:

```php
class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        Response::macro('success', function ($data) {
            return Response::json([
                'success' => true,
                'data' => $data,
            ]);
        });
    }
}
```

Make sure the facade is imported:

```php
use Illuminate\Support\Facades\Response;
```

---

## Why Use Response Macros?

Without macros:

```php
return response()->json([
    'success' => true,
    'message' => 'User created',
    'data' => $user,
], 201);
```

The same structure may be repeated in many controllers.

With a macro:

```php
return response()->success(
    $user,
    'User created',
    201
);
```

Benefits:

* Reduces repeated code.
* Provides reusable response methods.
* Helps maintain consistent API responses.
* Keeps controllers cleaner.
* Centralizes common response formatting.

---

## Response Macro vs Helper Function

Both can reduce repeated code, but they work differently.

### Response Macro

Extends Laravel's response API:

```php
return response()->success($data);
```

### Helper Function

Uses a separate function:

```php
return apiSuccess($data);
```

A response macro is useful when the custom behavior is specifically related to **HTTP responses**.

---

## Important Point

Response macros are **not required** for every Laravel API.

For simple applications, this is perfectly fine:

```php
return response()->json([
    'message' => 'Success',
    'data' => $data,
]);
```

Use macros when a repeated response pattern is common enough that centralizing it improves the codebase.

## Interview Point

**Q: What is a Response Macro in Laravel?**

**Answer:**
A Response Macro allows you to add custom reusable methods to Laravel's response factory.

Example:

```php
Response::macro('success', function ($data) {
    return Response::json([
        'success' => true,
        'data' => $data,
    ]);
});
```

Then:

```php
return response()->success($data);
```

**Q: Where are Response Macros usually registered?**

**Answer:**
They are commonly registered in a service provider's `boot()` method.

**Remember:**

```text
Repeated Response Logic
        ↓
   Response Macro
        ↓
Reusable Method
        ↓
response()->success(...)
```
