# 2.1 Basic Controllers

## Overview

A **Controller** is a PHP class used to handle HTTP request logic.

Controllers are stored in:

```text
app/Http/Controllers/
```

Instead of putting logic directly inside a route:

```php
Route::get('/users', function () {
    return 'User List';
});
```

Use a controller:

```php
Route::get('/users', [UserController::class, 'index']);
```

---

## Creating a Controller

```bash
php artisan make:controller UserController
```

Basic controller:

```php
<?php

namespace App\Http\Controllers;

class UserController
{
    public function index()
    {
        return 'User List';
    }
}
```

---

## Connecting Route to Controller

```php
use App\Http\Controllers\UserController;

Route::get('/users', [UserController::class, 'index']);
```

### Syntax

```php
Route::method('URI', [Controller::class, 'method']);
```

### Flow

```text
Request
   ↓
Route
   ↓
Controller Method
   ↓
Response
```

---

## Controller Methods

A controller can contain multiple methods:

```php
class UserController
{
    public function index()
    {
        return 'User List';
    }

    public function show($id)
    {
        return "User {$id}";
    }
}
```

Routes:

```php
Route::get('/users', [UserController::class, 'index']);
Route::get('/users/{id}', [UserController::class, 'show']);
```

---

## Route Parameters

Route parameters are passed to controller methods:

```php
Route::get('/users/{id}', [UserController::class, 'show']);
```

```php
public function show($id)
{
    return "User ID: {$id}";
}
```

Request:
```text
/users/10
```

Result:
```text
User ID: 10
```

---

## Returning a View

Controllers can return Blade views:

```php
public function index()
{
    return view('users.index');
}
```

This loads:

```text
resources/views/users/index.blade.php
```

### Passing Data

```php
public function index()
{
    $users = User::all();

    return view('users.index', [
        'users' => $users
    ]);
}
```

Or:

```php
return view('users.index', compact('users'));
```

---

## Controller with Model

Controllers commonly use Eloquent models:

```php
use App\Models\User;

public function index()
{
    $users = User::all();

    return view('users.index', compact('users'));
}
```

Typical flow:

```text
Request
   ↓
Route
   ↓
Controller
   ↓
Model / Database
   ↓
View / Response
```

---

## Dependency Injection

Controllers can receive dependencies through their constructor:

```php
public function __construct(
    private UserService $userService
) {
}
```

Laravel's **Service Container** resolves the dependency automatically.

Covered in detail in:

```text
2.4 Dependency Injection
```

---

## Controller vs Route Closure

### Route Closure

```php
Route::get('/users', function () {
    return User::all();
});
```

### Controller

```php
Route::get('/users', [UserController::class, 'index']);
```

Controllers are preferred when request logic becomes more complex because they provide better organization and maintainability.

# Interview Questions

### 1. What is a Controller?

A PHP class that handles HTTP request logic and returns a response.

### 2. Where are controllers stored?

```text
app/Http/Controllers/
```

### 3. How do you create a controller?

```bash
php artisan make:controller UserController
```

### 4. How do you connect a controller to a route?

```php
Route::get('/users', [UserController::class, 'index']);
```

### 5. Can controllers receive route parameters?

Yes.

```php
Route::get('/users/{id}', [UserController::class, 'show']);

public function show($id)
{
    return $id;
}
```

### 6. Can a controller return a view?

Yes.

```php
return view('users.index');
```

### 7. What is the purpose of a controller?

To organize HTTP request handling separately from route definitions.

---

# Key Takeaways

- Controllers handle HTTP request logic.
- Controllers are located in `app/Http/Controllers/`.
- Create controllers using `php artisan make:controller`.
- Routes connect URLs to controller methods.
- Controller methods can receive route parameters.
- Controllers can return views, JSON, redirects, and other responses.
- Controllers commonly work with Models and Services.
- Use Controllers instead of putting complex logic directly in routes.
