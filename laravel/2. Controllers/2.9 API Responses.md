# 2.9 API Responses

## Overview

An **API Response** is the data Laravel sends back to a client such as:

* Mobile applications
* React/Vue/Angular applications
* JavaScript/AJAX requests
* Other servers
* Third-party applications

APIs commonly return **JSON** instead of HTML.

```text
Client
   ↓
API Request
   ↓
Laravel Controller
   ↓
Business Logic
   ↓
JSON Response
   ↓
Client
```

---

## Basic JSON Response

Use `response()->json()`:

```php
public function index()
{
    return response()->json([
        'message' => 'Success',
        'data' => [],
    ]);
}
```

Response:

```json
{
    "message": "Success",
    "data": []
}
```

---

## HTTP Status Codes

API responses should use appropriate HTTP status codes.

```php
return response()->json([
    'message' => 'User created successfully',
    'data' => $user,
], 201);
```

Common codes:

| Status | Meaning               | Common API Usage                         |
| ------ | --------------------- | ---------------------------------------- |
| `200`  | OK                    | Successful request                       |
| `201`  | Created               | Resource created                         |
| `204`  | No Content            | Successful request with no response body |
| `400`  | Bad Request           | Invalid request                          |
| `401`  | Unauthorized          | Authentication required/failed           |
| `403`  | Forbidden             | User is not allowed                      |
| `404`  | Not Found             | Resource does not exist                  |
| `422`  | Unprocessable Content | Validation failed                        |
| `500`  | Server Error          | Unexpected server error                  |

---

## Successful API Response

Example:

```php
public function show(User $user)
{
    return response()->json([
        'message' => 'User retrieved successfully',
        'data' => $user,
    ]);
}
```

Response:

```json
{
    "message": "User retrieved successfully",
    "data": {
        "id": 1,
        "name": "Aman",
        "email": "aman@example.com"
    }
}
```

---

## Error Response

Return a meaningful error message:

```php
return response()->json([
    'message' => 'User not found',
], 404);
```

Response:

```json
{
    "message": "User not found"
}
```

---

## Validation Error Response

Laravel automatically returns validation errors for API requests.

Example validation:

```php
$request->validate([
    'email' => ['required', 'email'],
]);
```

A validation failure can return:

```json
{
    "message": "The email field is required.",
    "errors": {
        "email": [
            "The email field is required."
        ]
    }
}
```

The status code is typically:

```text
422 Unprocessable Content
```

---

## Returning Collections

You can return multiple records:

```php
public function index()
{
    $users = User::all();

    return response()->json([
        'data' => $users,
    ]);
}
```

Response:

```json
{
    "data": [
        {
            "id": 1,
            "name": "Aman"
        },
        {
            "id": 2,
            "name": "John"
        }
    ]
}
```

---

## API Resources

For larger APIs, use **API Resources** to control the JSON structure.

Create a resource:

```bash
php artisan make:resource UserResource
```

Example:

```php
class UserResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'email' => $this->email,
        ];
    }
}
```

Controller:

```php
public function show(User $user)
{
    return new UserResource($user);
}
```

This gives you control over which model fields are exposed.

---

## Resource Collection

For multiple records:

```php
public function index()
{
    $users = User::all();

    return UserResource::collection($users);
}
```

This is useful for keeping API responses consistent.

---

## API Response with Metadata

You can include additional information:

```php
return response()->json([
    'message' => 'Users retrieved successfully',
    'data' => $users,
    'meta' => [
        'total' => $users->count(),
    ],
]);
```

Response:

```json
{
    "message": "Users retrieved successfully",
    "data": [],
    "meta": {
        "total": 10
    }
}
```

---

## API Response with Pagination

For large datasets, use pagination:

```php
public function index()
{
    $users = User::paginate(10);

    return response()->json($users);
}
```

Laravel includes pagination information such as:

```text
current_page
last_page
per_page
total
```

and links for navigating between pages.

---

## API Response Headers

You can add headers:

```php
return response()
    ->json([
        'message' => 'Success',
    ])
    ->header('X-App-Version', '1.0');
```

Headers can provide additional information about the response.

## API Response vs Web Response

### Web Application

Usually returns HTML:

```php
return view('users.index');
```

```text
Laravel
   ↓
Blade
   ↓
HTML
   ↓
Browser
```

### API

Usually returns JSON:

```php
return response()->json([
    'data' => $users,
]);
```

```text
Laravel
   ↓
JSON
   ↓
React / Mobile App / Other Client
```

## Consistent API Structure

A project may define a standard response format:

```json
{
    "success": true,
    "message": "User created successfully",
    "data": {
        "id": 1,
        "name": "Aman"
    }
}
```

Error:

```json
{
    "success": false,
    "message": "Validation failed",
    "errors": {
        "email": [
            "The email field is required."
        ]
    }
}
```

The exact structure is a **project/API design decision**. Laravel does not require every API to use a `success` field.

---

## Best Practices

### 1. Use Appropriate Status Codes

```php
return response()->json($data, 201);
```

for successful resource creation.

### 2. Don't Expose Unnecessary Fields

Instead of returning an entire model:

```php
return response()->json($user);
```

consider using an API Resource:

```php
return new UserResource($user);
```

This gives you control over the API output.

### 3. Keep Responses Consistent

Use a predictable structure for similar endpoints.

### 4. Use Pagination

Avoid returning thousands of records in one response.

```php
User::paginate(20);
```
