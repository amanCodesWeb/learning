# 2.4 Dependency Injection

## Overview

**Dependency Injection (DI)** means providing a class with the objects or services it needs instead of creating them inside the class.

Laravel uses its **Service Container** to automatically resolve and inject dependencies.

---

## Without Dependency Injection

A class creates its own dependency:

```php
class OrderController extends Controller
{
    public function store()
    {
        $paymentService = new PaymentService();
        $paymentService->process();
        return "Order created";
    }
}
```

The controller is tightly coupled to `PaymentService`.

---

## With Dependency Injection

Pass the dependency into the constructor:

```php
class OrderController extends Controller
{
    public function __construct(
        private PaymentService $paymentService
    ) {}

    public function store()
    {
        $this->paymentService->process();

        return "Order created";
    }
}
```

Laravel automatically creates and injects `PaymentService`.

---

## Method Injection

Dependencies can also be injected directly into controller methods:

```php
class OrderController extends Controller
{
    public function store(
        Request $request,
        PaymentService $paymentService
    ) {
        $paymentService->process($request->all());

        return "Order created";
    }
}
```

Laravel resolves both dependencies automatically.

---

## Constructor vs Method Injection

### Constructor Injection

Use when the dependency is required by multiple methods:

```php
public function __construct(
    private OrderService $orderService
) {}
```

### Method Injection

Use when the dependency is needed only by a specific method:

```php
public function store(
    Request $request,
    PaymentService $paymentService
) {}
```

---

## Dependency Injection with Interfaces

DI becomes more powerful when using interfaces.

```php
interface PaymentGateway
{
    public function charge(float $amount);
}
```

Implementation:

```php
class StripePayment implements PaymentGateway
{
    public function charge(float $amount)
    {
        // Stripe payment logic
    }
}
```

Controller:

```php
class PaymentController extends Controller
{
    public function __construct(
        private PaymentGateway $paymentGateway
    ) {}

    public function store()
    {
        $this->paymentGateway->charge(100);
    }
}
```

Laravel needs to know which implementation should be used.

Register the binding:

```php
$this->app->bind(
    PaymentGateway::class,
    StripePayment::class
);
```

Now Laravel resolves:

```text
PaymentGateway
    ↓
Laravel Service Container
    ↓
StripePayment
```

---

## Laravel Service Container

The **Service Container** is responsible for creating and resolving dependencies.

Example:

```php
public function __construct(
    OrderService $orderService
) {}
```

Laravel sees:

```text
OrderController
    ↓
needs OrderService
    ↓
Service Container
    ↓
creates OrderService
    ↓
injects it into Controller
```

---

## Why Use Dependency Injection?

DI provides:

* **Loose coupling** between classes.
* Easier **testing**.
* Easier replacement of implementations.
* Better **maintainability**.
* Cleaner and more reusable code.

Example:

```php
// Bad
$payment = new StripePayment();

// Better
$payment = $this->paymentGateway;
```

The second approach allows the implementation to be changed without changing the controller.

---

## Dependency Injection vs Creating Objects

### Creating Dependency Yourself

```php
class OrderService
{
    public function __construct()
    {
        $this->payment = new StripePayment();
    }
}
```

`OrderService` is directly dependent on `StripePayment`.

### Using Dependency Injection

```php
class OrderService
{
    public function __construct(
        private PaymentGateway $payment
    ) {}
}
```

Now `OrderService` depends on the **abstraction**, not a specific implementation.

---

## Practical Example

```php
class OrderController extends Controller
{
    public function __construct(
        private OrderService $orderService
    ) {}

    public function store(Request $request)
    {
        $order = $this->orderService->create(
            $request->all()
        );

        return response()->json($order);
    }
}
```

## Interview Point

**Q: What is Dependency Injection in Laravel?**

**Answer:**
Dependency Injection is a technique where a class receives the objects or services it depends on instead of creating them itself. Laravel's Service Container automatically resolves and injects many dependencies.

**Q: What is the benefit of DI?**

**Answer:**
It reduces tight coupling, improves testability, makes implementations easier to replace, and keeps code maintainable.

**Remember:**

```text
Without DI:
Class → creates dependency

With DI:
Class → declares dependency
          ↓
    Service Container
          ↓
      provides it
```
