# 2.8 Redirect Responses

## Overview

A **Redirect Response** tells the browser to make a new request to another URL.

Redirects are commonly used after:

* Form submission
* Login/logout
* Creating or updating records
* Deleting records
* Moving users between pages

```text
Request
   ↓
Controller
   ↓
Redirect Response
   ↓
Browser
   ↓
New Request
   ↓
Target URL
```

---

## Basic Redirect

Redirect to a URL:

```php
return redirect('/users');
```

Laravel sends a redirect response to the browser, and the browser then requests:

```text
/users
```

---

## Redirect to a Named Route

Named routes are usually preferred because the URL can change without changing the controller code.

Route:

```php
Route::get('/users', [UserController::class, 'index'])
    ->name('users.index');
```

Redirect:

```php
return redirect()->route('users.index');
```

---

## Redirect with Route Parameters

Route:

```php
Route::get('/users/{id}', [UserController::class, 'show'])
    ->name('users.show');
```

Redirect with parameter:

```php
return redirect()->route('users.show', ['id' => $user->id]);
```

You can also pass the model:

```php
return redirect()->route('users.show', $user);
```

---

## Redirect Back

Return the user to the previous page:

```php
return redirect()->back();
```

This is useful after form validation or an operation where the user should remain on the previous page.

---

## Redirect Back with Input

You can send the submitted input back to the previous request:

```php
return redirect()
    ->back()
    ->withInput();
```

The old input can then be accessed in Blade:

```php
{{ old('name') }}
```

Example:

```php
<input
    type="text"
    name="name"
    value="{{ old('name') }}"
>
```

This is useful when a form fails validation and the user should not have to re-enter everything.

---

## Redirect with Flash Data

You can attach temporary session data to a redirect:

```php
return redirect()
    ->route('users.index')
    ->with('success', 'User created successfully.');
```

The message is stored in the session for the next request.

In Blade:

```php
@if (session('success'))
    <div>{{ session('success') }}</div>
@endif
```

Common examples:

```php
->with('success', 'Saved successfully.')
->with('error', 'Something went wrong.')
->with('warning', 'Please check your input.')
```

---

## Redirect After Form Submission

A common Laravel pattern is:

```php
public function store(StoreUserRequest $request)
{
    $user = User::create(
        $request->validated()
    );

    return redirect()
        ->route('users.index')
        ->with('success', 'User created successfully.');
}
```

Flow:

```text
POST /users
     ↓
Validate Request
     ↓
Create User
     ↓
Redirect
     ↓
GET /users
```

This pattern is commonly known as **Post/Redirect/Get (PRG)**.

It helps prevent accidental form resubmission when the user refreshes the resulting page.

---

## Redirect with Status Code

Laravel normally uses an HTTP `302` redirect:

```php
return redirect('/users');
```

You can specify another redirect status:

```php
return redirect('/users', 301);
```

Common redirect status codes:

| Status | Meaning                                         |
| ------ | ----------------------------------------------- |
| `301`  | Permanent redirect                              |
| `302`  | Temporary redirect                              |
| `303`  | See Other                                       |
| `307`  | Temporary redirect while preserving HTTP method |
| `308`  | Permanent redirect while preserving HTTP method |

For normal form submissions, Laravel's standard redirect is generally sufficient.

---

## Redirect to External URL

You can redirect to an external URL:

```php
return redirect()->away('https://example.com');
```

Use this when the destination is outside your Laravel application.

---

## Redirect to Intended URL

Laravel can redirect a user to the URL they originally wanted to access.

```php
return redirect()->intended('/dashboard');
```

Example:

```text
User requests /profile
        ↓
Authentication required
        ↓
User logs in
        ↓
Redirect to /profile
```

If no intended URL exists, Laravel uses:

```text
/dashboard
```

as the fallback.

---

## Redirect from Middleware

Redirects are also commonly used in middleware.

```php
public function handle($request, Closure $next)
{
    if (! auth()->check()) {
        return redirect()->route('login');
    }

    return $next($request);
}
```

Flow:

```text
Request
   ↓
Middleware
   ↓
Authenticated?
   ├── No → Redirect to Login
   └── Yes → Controller
```

---

## Redirect vs Response

A redirect does **not** directly return the target page.

It tells the browser to make another request.

```text
Normal Response:

Browser → Laravel
Browser ← HTML/JSON


Redirect:

Browser → Laravel
Browser ← 302 Redirect
Browser → New URL
Browser ← Response
```

---

## Redirect vs `view()`

### Return a View

```php
return view('users.index');
```

Laravel renders the view during the current request.

### Redirect

```php
return redirect()->route('users.index');
```

Laravel tells the browser to make a new request to the route.

---

## Best Practices

Prefer named routes:

```php
return redirect()->route('users.index');
```

instead of hard-coded URLs:

```php
return redirect('/users');
```

After successful form submissions, a common pattern is:

```php
return redirect()
    ->route('users.index')
    ->with('success', 'User created successfully.');
```

Use `withInput()` when the previous form needs its submitted values preserved.

## Interview Point

**Q: What is a redirect response in Laravel?**

**Answer:**
A redirect response tells the browser to make a new request to another URL or route.

**Q: How do you redirect to a named route?**

```php
return redirect()->route('users.index');
```

**Q: How do you redirect back?**

```php
return redirect()->back();
```

**Q: How do you send a success message with a redirect?**

```php
return redirect()
    ->route('users.index')
    ->with('success', 'User created successfully.');
```

**Q: What is the difference between `redirect()` and `view()`?**

```text
view()
   ↓
Render view in current request

redirect()
   ↓
Tell browser to make a new request
```

**Remember:**

```text
Form Submit
    ↓
Controller
    ↓
Process Data
    ↓
Redirect
    ↓
New GET Request
    ↓
Display Page
```
