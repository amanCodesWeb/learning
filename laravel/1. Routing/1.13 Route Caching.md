# 1.13 Route Caching

## Overview

**Route Caching** improves application performance by storing all routes in a compiled cache file. Instead of parsing route files on every request, Laravel loads the cached routes, resulting in faster route registration.

Route caching is mainly used in **production environments**.

---

# Cache Routes

Generate the route cache.

```bash
php artisan route:cache
```
---

# Clear Route Cache

Remove the cached routes.

```bash
php artisan route:clear
```

---

# Rebuild Route Cache

After modifying any route file, regenerate the cache.

```bash
php artisan route:clear

php artisan route:cache
```

---

# View Registered Routes

```bash
php artisan route:list
```

Useful for verifying routes before caching.

---

# How Route Caching Works

Without Route Cache:
Request
    │
    ▼
Read routes/web.php
Read routes/api.php
Register Routes
    │
    ▼
Match Route


With Route Cache:
Request
    │
    ▼
Load Cached Routes
    │
    ▼
Match Route

---

# Route Cache File

Laravel stores the compiled routes in:
bootstrap/cache/

You should **never edit** this file manually.

---

# Important Notes

- After adding, removing, or modifying routes, regenerate the cache.
- Route caching is recommended only in **production**.
- During development, it's usually disabled because routes change frequently.

---

# Route Caching Limitation

**Routes using Closures cannot be cached.**

❌ Not cacheable:

```php
Route::get('/', function () {
    return 'Home';
});
```

✅ Cacheable:

```php
Route::get('/', [
    HomeController::class,
    'index'
]);
```

Use controller actions for production applications.

---

# Best Practices

- Use route caching in production.
- Prefer controller-based routes.
- Rebuild the cache after route changes.
- Verify routes using `php artisan route:list`.

---

# Common Mistakes

- Forgetting to regenerate the cache after changing routes.
- Trying to cache Closure-based routes.
- Using route caching during active development.
- Editing cached files manually.

---

# Interview Questions

### 1. What is Route Caching?

**Answer:**  
Route Caching compiles and stores all application routes in a cache file to improve route registration performance.

---

### 2. Which command creates the route cache?

**Answer:**

```bash
php artisan route:cache
```

---

### 3. Which command clears the route cache?

**Answer:**

```bash
php artisan route:clear
```

---

### 4. Should Route Caching be used in development?

**Answer:**  
Generally, **no**. Route files change frequently during development, so caching would require constant rebuilding.

---

### 5. Can Closure routes be cached?

**Answer:**  
**No.** Route caching supports only controller-based routes.

---

# Key Takeaways

- Route Caching improves application performance.
- Use `php artisan route:cache` in production.
- Clear the cache with `php artisan route:clear`.
- Rebuild the cache whenever routes change.
- Use controller actions instead of Closures for cacheable routes.
