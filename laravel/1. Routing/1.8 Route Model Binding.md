# 1.8 Route Model Binding

## Overview

**Route Model Binding** automatically resolves route parameters into **Eloquent model instances**, eliminating the need to manually query the database.

Instead of retrieving a model with `find()` or `findOrFail()`, Laravel injects the model directly into your route or controller.

---

# Without Route Model Binding

```php
Route::get('/users/{id}', [UserController::class, 'show']);
```

```php
public function show($id)
{
    $user = User::findOrFail($id);
    return $user;
}
```

---

# With Implicit Route Model Binding

```php
Route::get('/users/{user}', [UserController::class, 'show']);
```

```php
public function show(User $user)
{
    return $user;
}
```

Laravel automatically executes:

```php
User::findOrFail($id);
```

---

# How It Works

Laravel matches:
Route Parameter

```php
{user}
```

with

```php
User $user
```

The parameter name **must match** the variable name.

---

# Custom Route Key

By default, Laravel uses the **id** column.
Use another column such as `slug`.

```php
Route::get('/posts/{post:slug}', function (Post $post) {
    return $post;
});
```

URL:
/posts/laravel-routing

Laravel automatically executes:

```php
Post::where('slug', 'laravel-routing')->firstOrFail();
```

---

# Using getRouteKeyName()

To always use a different route key:

```php
class Post extends Model
{
    public function getRouteKeyName()
    {
        return 'slug';
    }
}
```

Now every route uses the `slug` column automatically.

---

# Scoped Route Model Binding

Useful for nested resources.

```php
Route::get('/users/{user}/posts/{post}', function (User $user, Post $post) {
    //
});
```

Enable scoped binding:

```php
Route::scopeBindings()->group(function () {

    Route::get('/users/{user}/posts/{post}', function (User $user, Post $post) {
        //
    });

});
```

Laravel ensures the post belongs to the specified user.

---

# Explicit Route Model Binding

Define custom binding manually.

In `AppServiceProvider`:

```php
use Illuminate\Support\Facades\Route;
use App\Models\User;

public function boot(): void
{
    Route::model('user', User::class);
}
```

Or customize the query:

```php
Route::bind('user', function ($value) {
    return User::where('username', $value)->firstOrFail();
});
```

---

# Missing Models

Handle missing models gracefully.

```php
Route::get('/users/{user}', function (User $user) {
    return $user;
})->missing(function () {
    return redirect('/users');
});
```

---

# Soft Deleted Models

Include soft-deleted models.

```php
Route::get('/users/{user}', function (User $user) {
    return $user;
})->withTrashed();
```

---

# Best Practices

- Prefer implicit Route Model Binding.
- Use meaningful parameter names.
- Use slugs instead of IDs for public URLs when appropriate.
- Use scoped bindings for nested resources.
- Let Laravel return a 404 automatically when a model is not found.

---

# Common Mistakes

- Route parameter name doesn't match the controller variable.

❌ Wrong

```php
Route::get('/users/{id}', ...);

public function show(User $user)
```

✅ Correct

```php
Route::get('/users/{user}', ...);

public function show(User $user)
```

- Manually querying models that Laravel can resolve automatically.
- Forgetting to use scoped bindings for nested resources.

---

# Interview Questions

### 1. What is Route Model Binding?

**Answer:**  
Route Model Binding automatically resolves route parameters into Eloquent model instances.

---

### 2. What is the difference between Implicit and Explicit Route Model Binding?

**Answer:**

- **Implicit:** Laravel resolves the model automatically based on the route parameter and type hint.
- **Explicit:** The developer manually defines how a route parameter should resolve to a model.

---

### 3. How do you use a slug instead of an ID?

**Answer:**

```php
Route::get('/posts/{post:slug}', function (Post $post) {
    //
});
```

Or override:

```php
public function getRouteKeyName()
{
    return 'slug';
}
```

---

### 4. What happens if the model is not found?

**Answer:**  
Laravel automatically throws a **404 Not Found** response unless a custom `missing()` callback is defined.

---

### 5. What is Scoped Route Model Binding?

**Answer:**  
It ensures nested models belong to their parent model. For example, a `Post` must belong to the specified `User`.

---

# Key Takeaways

- Route Model Binding automatically injects Eloquent models.
- Implicit binding is the preferred approach.
- Use custom route keys (e.g., `slug`) for friendly URLs.
- Use scoped bindings for nested resources.
- Laravel automatically returns a 404 for missing models.
