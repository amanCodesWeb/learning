# 1.1 Basic Routes

## Overview

A **Route** defines how Laravel responds to an incoming HTTP request. It maps a URL and HTTP method to a Closure or Controller action.

Routes are primarily defined in:

- `routes/web.php` → Web routes (sessions, cookies, CSRF)
- `routes/api.php` → API routes (stateless, if installed)

---

# Basic Route Syntax

```php
use Illuminate\Support\Facades\Route;

Route::get('/', function () {
    return 'Welcome to Laravel!';
});
```

**Syntax:**

```php
Route::method('URI', Action);
```

- **method** → HTTP method (`get`, `post`, `put`, `patch`, `delete`, `options`, `match`, `any`)
- **URI** → Requested URL
- **Action** → Closure or Controller method

---

# HTTP Methods

### GET

Retrieve data.

```php
Route::get('/users', function () {
    return 'User List';
});
```

---

### POST

Create new data.

```php
Route::post('/users', function () {
    return 'User Created';
});
```

---

### PUT

Update an entire resource.

```php
Route::put('/users/{id}', function ($id) {
    return "Updated User {$id}";
});
```

---

### PATCH

Update part of a resource.

```php
Route::patch('/users/{id}', function ($id) {
    return "Patched User {$id}";
});
```

---

### DELETE

Delete a resource.

```php
Route::delete('/users/{id}', function ($id) {
    return "Deleted User {$id}";
});
```

---

### Match Multiple Methods

```php
Route::match(['get', 'post'], '/contact', function () {
    return 'Contact Page';
});
```

---

### Any Method

```php
Route::any('/search', function () {
    return 'Search';
});
```

---

# Route Using Controller

Instead of a Closure, routes usually point to a controller.

```php
use App\Http\Controllers\UserController;

Route::get('/users', [UserController::class, 'index']);
```

---

# View Route

Return a view without creating a controller.

```php
Route::view('/about', 'about');
```

Equivalent to:

```php
Route::get('/about', function () {
    return view('about');
});
```

---

# Redirect Route

Redirect one URL to another.

```php
Route::redirect('/home', '/dashboard');
```

---

# Route List

Display all registered routes.

```bash
php artisan route:list
```

Useful for debugging routes.

---

# Best Practices

- Use controllers instead of Closures for production applications.
- Follow RESTful HTTP methods (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`).
- Keep routes simple and readable.
- Organize routes into `web.php` and `api.php`.

---

# Interview Questions

### 1. What is routing in Laravel?

**Answer:**  
Routing maps an incoming HTTP request (URL + HTTP method) to a Closure or Controller action.

---

### 2. Which file contains web routes?

**Answer:**

```
routes/web.php
```

---

### 3. What command lists all registered routes?

**Answer:**

```bash
php artisan route:list
```

---

### 4. What is the difference between GET and POST?

**Answer:**

- **GET** → Retrieve data.
- **POST** → Create or submit data.

---

### 5. Why are controllers preferred over Closures?

**Answer:**  
Controllers improve code organization, reusability, maintainability, and testability. Closures are suitable only for very simple routes or quick testing.

---

# Key Takeaways

- Routes map URLs to application logic.
- Routes are usually defined in `routes/web.php` or `routes/api.php`.
- Laravel supports all standard HTTP methods.
- Prefer controllers over Closures in real applications.
- Use `php artisan route:list` to inspect registered routes.
