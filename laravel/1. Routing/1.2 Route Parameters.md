# 1.2 Route Parameters

## Overview

**Route Parameters** allow you to capture dynamic values from the URL and pass them to a Closure or Controller.

Example URL:
/users/10

Here, `10` is a route parameter.

---

# Required Parameters

A required parameter must always be present in the URL.

```php
Route::get('/users/{id}', function ($id) {
    return "User ID: $id";
});
```

URL:
/users/10

Output:
User ID: 10

---

# Multiple Parameters

You can define multiple parameters.

```php
Route::get('/users/{user}/posts/{post}', function ($user, $post) {
    return "User: $user, Post: $post";
});
```

URL:
/users/5/posts/20

Output:
User: 5, Post: 20

---

# Optional Parameters

Optional parameters use `?` and must have a default value.

```php
Route::get('/users/{name?}', function ($name = 'Guest') {
    return "Hello, $name";
});
```

URLs:
/users
/users/Aman

Output:
Hello, Guest
Hello, Aman

---

# Route Parameter Constraints

Restrict parameter values using `where()`.

### Numbers Only

```php
Route::get('/users/{id}', function ($id) {
    return $id;
})->where('id', '[0-9]+');
```

---

### Alphabets Only

```php
Route::get('/users/{name}', function ($name) {
    return $name;
})->where('name', '[A-Za-z]+');
```

---

### Multiple Constraints

```php
Route::get('/posts/{year}/{month}', function ($year, $month) {
    //
})->where([
    'year' => '[0-9]{4}',
    'month' => '[0-9]{2}',
]);
```

---

# Global Constraints

Define reusable constraints in `AppServiceProvider`.

```php
Route::pattern('id', '[0-9]+');
```

Now every `{id}` parameter accepts only numbers.

---

# Encoded Forward Slashes

By default, route parameters cannot contain `/`.
If needed, allow it using:

```php
Route::get('/search/{search}', function ($search) {
    return $search;
})->where('search', '.*');
```

---

# Accessing Parameters in Controller

```php
Route::get('/users/{id}', [UserController::class, 'show']);
```

```php
public function show($id)
{
    return $id;
}
```

---

# Best Practices

- Use meaningful parameter names (`{user}`, `{post}`) instead of generic ones.
- Apply constraints when possible.
- Use Route Model Binding (covered later) instead of manually fetching models.
- Keep URLs clean and RESTful.

---

# Common Mistakes

- Forgetting to provide a default value for optional parameters.
- Using incorrect parameter names between the route and controller.
- Not validating or constraining parameters.
- Fetching models manually when Route Model Binding can be used.

---

# Interview Questions

### 1. What are Route Parameters?

**Answer:**  
Route parameters are dynamic values in the URL that Laravel captures and passes to a Closure or Controller.

---

### 2. What is the difference between required and optional parameters?

**Answer:**

- **Required:** Must be present in the URL.
- **Optional:** May be omitted and require a default value.

---

### 3. How do you make a route parameter optional?

**Answer:**

```php
Route::get('/users/{name?}', function ($name = 'Guest') {
    //
});
```

---

### 4. How do you restrict a route parameter to numbers?

**Answer:**

```php
->where('id', '[0-9]+')
```

---

### 5. How do you define multiple route parameter constraints?

**Answer:**

```php
->where([
    'year' => '[0-9]{4}',
    'month' => '[0-9]{2}',
])
```

---

# Key Takeaways

- Route parameters capture dynamic values from the URL.
- Parameters can be **required** or **optional**.
- Use `where()` to apply validation rules.
- Use descriptive parameter names.
- Prefer Route Model Binding for Eloquent models.
