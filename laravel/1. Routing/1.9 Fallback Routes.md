# 1.9 Fallback Routes

## Overview

A **Fallback Route** is executed when no other route matches the incoming request.

It is commonly used to display a custom **404 Not Found** page or return a custom JSON response for APIs.

> **Important:** The fallback route **must be the last route** defined in the route file.

---

# Basic Fallback Route

```php
use Illuminate\Support\Facades\Route;

Route::fallback(function () {
    return '404 - Page Not Found';
});
```

If no route matches, Laravel executes this route.

---

# Returning a View

Display a custom 404 page.

```php
Route::fallback(function () {
    return response()->view('errors.404', [], 404);
});
```

---

# Redirecting

Redirect unknown URLs.

```php
Route::fallback(function () {
    return redirect('/');
});
```

---

# API Fallback Route

For APIs, return a JSON response.

```php
Route::fallback(function () {
    return response()->json([
        'message' => 'Endpoint not found.'
    ], 404);
});
```

---

# Controller Fallback

For larger applications, you can use a controller.

```php
Route::fallback([
    ErrorController::class,
    'notFound'
]);
```

Controller:

```php
public function notFound()
{
    return response()->view('errors.404', [], 404);
}
```

---

# Route Order

✅ Correct

```php
Route::get('/', function () {
    //
});

Route::get('/users', function () {
    //
});

Route::fallback(function () {
    //
});
```

❌ Incorrect

```php
Route::fallback(function () {
    //
});

Route::get('/users', function () {
    //
});
```

Always place the fallback route **last**.

---

# Fallback Route vs 404 Error Page

| Fallback Route | 404 Error Page |
|---------------|----------------|
| Executed when no route matches | Displayed when a 404 response is returned |
| Can return views, JSON, or redirects | Usually a Blade view (`resources/views/errors/404.blade.php`) |
| Allows custom logic before responding | Focuses on displaying the error page |

---

# Best Practices

- Place the fallback route at the end of the route file.
- Return JSON for API routes.
- Return a custom 404 view for web routes.
- Keep fallback logic simple.

---

# Common Mistakes

- Defining the fallback route before other routes.
- Returning HTTP 200 instead of HTTP 404.
- Mixing API and web fallback responses.
- Putting business logic inside the fallback route.

---

# Interview Questions

### 1. What is a Fallback Route?

**Answer:**  
A Fallback Route handles requests when no other defined route matches the incoming URL.

---

### 2. When is a Fallback Route executed?

**Answer:**  
It is executed only after Laravel fails to match any other route.

---

### 3. Where should a Fallback Route be placed?

**Answer:**  
It should always be the **last route** in the route file.

---

### 4. How do you return a JSON 404 response?

**Answer:**

```php
Route::fallback(function () {
    return response()->json([
        'message' => 'Endpoint not found.'
    ], 404);
});
```

---

### 5. Can a Fallback Route return a view?

**Answer:**  
Yes.

```php
return response()->view('errors.404', [], 404);
```

---

# Key Takeaways

- `Route::fallback()` handles unmatched routes.
- It must be the **last route** in the route file.
- Use it to return custom 404 pages or JSON responses.
- Always return the correct **404 HTTP status code**.
- Keep fallback logic minimal and focused.
