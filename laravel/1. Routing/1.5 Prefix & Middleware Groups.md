# 1.5 Prefix & Middleware Groups

## Overview

**Prefix** and **Middleware Groups** are commonly used together to organize routes and apply shared behavior. They help create clean, maintainable route files by avoiding repetitive code.

---

# Prefix Groups

The `prefix()` method adds a common URI prefix to all routes in the group.

```php
Route::prefix('admin')->group(function () {

    Route::get('/dashboard', function () {
        //
    });

    Route::get('/users', function () {
        //
    });

});
```

Generated URLs:
/admin/dashboard
/admin/users

---

# Middleware Groups

The `middleware()` method applies one or more middleware to every route in the group.

```php
Route::middleware('auth')->group(function () {

    Route::get('/dashboard', function () {
        //
    });

    Route::get('/profile', function () {
        //
    });

});
```

Multiple middleware:

```php
Route::middleware([
    'auth',
    'verified'
])->group(function () {

    Route::get('/dashboard', function () {
        //
    });

});
```

---

# Combining Prefix + Middleware

In real projects, these are usually used together.

```php
Route::prefix('admin')
    ->middleware(['auth'])
    ->group(function () {

        Route::get('/dashboard', function () {
            //
        });

        Route::get('/users', function () {
            //
        });

    });
```

---

# Prefix + Middleware + Name

A common Laravel pattern:

```php
Route::prefix('admin')
    ->middleware(['auth'])
    ->name('admin.')
    ->group(function () {

        Route::get('/dashboard', function () {
            //
        })->name('dashboard');

        Route::get('/users', function () {
            //
        })->name('users');

    });
```

Route Names:
admin.dashboard
admin.users

URLs:
/admin/dashboard
/admin/users

---

# Real-World Example

```php
Route::prefix('admin')
    ->middleware(['auth', 'verified'])
    ->controller(AdminController::class)
    ->name('admin.')
    ->group(function () {

        Route::get('/dashboard', 'dashboard')->name('dashboard');
        Route::get('/orders', 'orders')->name('orders');
        Route::get('/products', 'products')->name('products');

    });
```

This is a common structure used in production Laravel applications.

---

# Best Practices

- Group routes with the same prefix and middleware.
- Apply middleware to groups instead of individual routes.
- Use descriptive prefixes like `admin`, `api`, or `customer`.
- Combine `prefix()`, `middleware()`, and `name()` for better organization.
- Avoid deeply nested route groups.

---

# Common Mistakes

- Applying the same middleware repeatedly to individual routes.
- Creating unnecessary nested groups.
- Using inconsistent URL prefixes.
- Forgetting route name prefixes for grouped routes.

---

# Interview Questions

### 1. Why use Prefix Groups?

**Answer:**  
To add a common URL prefix to multiple routes, reducing repetition and improving organization.

---

### 2. Why use Middleware Groups?

**Answer:**  
To apply the same middleware to multiple routes without repeating the middleware definition.

---

### 3. Can multiple middleware be applied to a route group?

**Answer:**  
Yes.

```php
Route::middleware(['auth', 'verified'])->group(function () {
    //
});
```

---

### 4. Can `prefix()`, `middleware()`, and `name()` be used together?

**Answer:**  
Yes. They are commonly combined in Laravel applications to organize related routes.

---

### 5. What is the advantage of grouping routes?

**Answer:**  
It reduces duplication, improves readability, and makes route management easier.

---

# Key Takeaways

- `prefix()` adds a common URL prefix.
- `middleware()` applies middleware to all routes in the group.
- Multiple middleware can be applied to a group.
- Combine `prefix()`, `middleware()`, and `name()` for clean route organization.
- This pattern is widely used in production Laravel applications.
