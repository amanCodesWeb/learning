# 0.5 MVC Architecture

## Overview

**MVC (Model-View-Controller)** is an architectural pattern used by Laravel to organize application code. It separates the application into three layers, making the code easier to understand, maintain, test, and scale.

---

# MVC Components

## Model

The **Model** is responsible for managing the application's data and business logic. It interacts with the database using **Eloquent ORM**.

**Responsibilities:**
- Retrieve data
- Insert data
- Update data
- Delete data
- Define relationships

**Example:**

```php
$user = User::find(1);
```

---

## View

The **View** is responsible for displaying data to the user. Laravel uses the **Blade Template Engine** for creating views.

**Responsibilities:**
- Display UI
- Show dynamic data
- Keep presentation separate from business logic

**Example:**

```blade
<h1>{{ $user->name }}</h1>
```

---

## Controller

The **Controller** acts as the middle layer between the Model and the View. It receives requests, processes them, communicates with the Model, and returns a response.

**Responsibilities:**
- Handle HTTP requests
- Validate data
- Call Models or Services
- Return Views, JSON, or Redirects

**Example:**

```php
public function show($id)
{
    $user = User::findOrFail($id);

    return view('users.show', compact('user'));
}
```

# Advantages of MVC

- Clear separation of concerns.
- Easier to maintain and scale.
- Better code reusability.
- Simplifies testing and debugging.
- Improves collaboration among developers.

---

# Best Practices

- Keep controllers thin.
- Put database logic in Models.
- Avoid database queries inside Views.
- Move complex business logic to Service classes when needed.
- Keep Views focused on presentation only.

---

# Common Mistakes

- Writing SQL queries directly in Controllers.
- Putting business logic inside Views.
- Creating large "God Controllers" with too much logic.
- Mixing HTML with database operations.

# Interview Questions

### 1. What is MVC?

**Answer:**  
MVC (Model-View-Controller) is an architectural pattern that separates an application into three layers: Model (data), View (UI), and Controller (request handling).

---

### 2. What is the role of a Model?

**Answer:**  
A Model manages data, business logic, and database interactions using Eloquent ORM.

---

### 3. What is the role of a Controller?

**Answer:**  
A Controller handles incoming requests, processes business logic, communicates with Models, and returns a response.

---

### 4. What is the role of a View?

**Answer:**  
A View is responsible for displaying data to the user. Laravel uses Blade as its templating engine.

---

### 5. Why does Laravel use MVC?

**Answer:**  
MVC improves code organization, maintainability, scalability, and separation of concerns by keeping data, business logic, and presentation independent.

---

# Key Takeaways

- **Model** → Handles data and database operations.
- **View** → Displays the user interface.
- **Controller** → Processes requests and coordinates between Model and View.
- MVC separates concerns, making applications easier to develop and maintain.
- Keep controllers thin and views free of business logic.
