# 0.3 Laravel Directory Structure

## Overview

Laravel follows a well-organized directory structure that separates different parts of the application, making it easier to develop, maintain, and scale. Each directory has a specific responsibility, and following Laravel's default structure is considered a best practice. :contentReference[oaicite:0]{index=0}

---

# Root Directory Structure

```text
app/
bootstrap/
config/
database/
public/
resources/
routes/
storage/
tests/
vendor/

.env
.env.example
artisan
composer.json
composer.lock
package.json
vite.config.js
phpunit.xml
```

---

# Directory Explanation

## app/

Contains the core application code.

**Default folders:**

- Http/
- Models/
- Providers/

**Created automatically when needed:**

- Console/
- Events/
- Exceptions/
- Jobs/
- Listeners/
- Mail/
- Notifications/
- Policies/
- Rules/
- Broadcasting/

> Almost all application logic is written inside the `app/` directory. :contentReference[oaicite:1]{index=1}

---

## bootstrap/

Bootstraps the Laravel application.

Contents:

```text
bootstrap/
├── app.php
└── cache/
```

- `app.php` → Creates and configures the Laravel application.
- `cache/` → Stores cached routes, services, and configuration.

---

## config/

Contains all configuration files.

Examples:

- app.php
- database.php
- cache.php
- queue.php
- mail.php
- filesystems.php

Access configuration values using:

```php
config('app.name');
```

---

## database/

Contains database-related files.

```text
database/
├── migrations/
├── factories/
├── seeders/
```

You can also store an SQLite database here if required.

---

## public/

The only directory accessible by the web server.

Contains:

- index.php (Application Entry Point)
- favicon.ico
- robots.txt
- build/ (Generated by Vite after build)

Never expose the project root directly.

---

## resources/

Contains application resources.

```text
resources/
├── views/
├── css/
└── js/
```

- Blade templates
- CSS
- JavaScript

---

## routes/

Contains route definitions.

**By default:**

- web.php
- console.php

**Optional (installed when needed):**

- api.php (`php artisan install:api`)
- channels.php (`php artisan install:broadcasting`)

---

## storage/

Stores files generated by Laravel.

```text
storage/
├── app/
├── framework/
└── logs/
```

Contains:

- Logs
- Cache
- Sessions
- Compiled Blade views
- User uploaded files

Create a public storage link using:

```bash
php artisan storage:link
```

---

## tests/

Contains Unit and Feature tests.

---

## vendor/

Contains Composer packages, including the Laravel framework.

> **Never modify files inside the `vendor/` directory.**

---

# Important Root Files

| File | Purpose |
|------|---------|
| `.env` | Environment variables |
| `.env.example` | Example environment configuration |
| `artisan` | Laravel CLI |
| `composer.json` | Project dependencies & autoloading |
| `composer.lock` | Locked dependency versions |
| `package.json` | Frontend dependencies |
| `vite.config.js` | Vite configuration |
| `phpunit.xml` | PHPUnit configuration |

---

# Best Practices

- Keep application logic inside `app/`.
- Never edit the `vendor/` directory.
- Store sensitive data in `.env`.
- Only expose the `public/` directory through the web server.
- Follow Laravel's default directory structure unless there's a strong reason not to.

---

# Interview Questions

### 1. Which directory contains the application logic?

**Answer:** `app/`

---

### 2. What is the purpose of the `public/` directory?

**Answer:** It is the web server entry point and contains `index.php`, which handles all incoming HTTP requests.

---

### 3. Where are Laravel routes defined?

**Answer:**

- `web.php`
- `console.php`

Optionally:

- `api.php`
- `channels.php`

---

### 4. What is stored in the `vendor/` directory?

**Answer:** Composer dependencies and the Laravel framework.

---

### 5. What is the purpose of `bootstrap/app.php`?

**Answer:** It bootstraps and configures the Laravel application before handling incoming requests.

---

# Key Takeaways

- `app/` → Application code
- `bootstrap/` → Application bootstrapping
- `config/` → Configuration files
- `database/` → Migrations, factories, seeders
- `public/` → Web entry point
- `resources/` → Views and frontend assets
- `routes/` → Route definitions
- `storage/` → Logs, cache, sessions, uploads
- `tests/` → Automated tests
- `vendor/` → Composer dependencies
- `.env` → Environment variables
- `artisan` → Laravel CLI
- `composer.json` → Project dependencies
