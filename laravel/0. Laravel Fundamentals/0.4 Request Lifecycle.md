# 0.4 Request Lifecycle

## Overview

The **Request Lifecycle** is the complete process Laravel follows to handle an incoming HTTP request and return a response to the browser.

Understanding this flow helps you know **where routing, middleware, controllers, service providers, and responses fit together**. It is one of the most commonly asked Laravel interview topics.

# Step-by-Step Explanation

### 1. Browser Sends Request

A user visits a URL such as:

```
https://example.com/products
```

The request first reaches Laravel's **public/index.php** file.

---

### 2. public/index.php

This is Laravel's **single entry point**.

Responsibilities:
- Starts the application
- Loads Composer's autoloader
- Loads the Laravel application
- Sends the request to the HTTP Kernel

---

### 3. Composer Autoload

```php
require __DIR__.'/../vendor/autoload.php';
```

Composer automatically loads all required PHP classes without manually including files.

---

### 4. bootstrap/app.php

Creates and configures the Laravel application.

It initializes:
- Application instance
- Service Container
- Routing
- Middleware
- Exception handling

---

### 5. HTTP Kernel

The HTTP Kernel receives the request and prepares it for processing.

Its responsibilities include:
- Bootstrapping Laravel
- Loading Service Providers
- Running Global Middleware
- Passing the request to the Router

---

### 6. Bootstrapping

Laravel prepares the application by:
- Loading environment variables
- Loading configuration files
- Registering facades
- Registering service providers
- Booting service providers

---

### 7. Service Providers

Service Providers register all application services into the Service Container.
They also perform application initialization during the `boot()` method.

---

### 8. Middleware

The request passes through middleware before reaching the route.

Examples:
- Authentication
- CSRF Protection
- Session Handling
- Rate Limiting

Middleware can:
- Continue the request
- Modify the request
- Stop the request
- Return a response

---

### 9. Router

Laravel matches the requested URL with a route defined in:
- `routes/web.php`
- `routes/api.php` (if installed)

Example:

```php
Route::get('/products', [ProductController::class, 'index']);
```

---

### 10. Controller

If a matching route is found, Laravel executes the corresponding controller method.

Example:

```php
public function index()
{
    return Product::all();
}
```

---

### 11. Response

The controller returns a response such as:
- Blade View
- JSON
- Redirect
- File Download

Laravel converts it into an HTTP response and sends it back to the browser.

---

# Simple Example

```php
Route::get('/hello', function () {
    return 'Hello Laravel!';
});
```

# Why is the Request Lifecycle Important?

Understanding the request lifecycle helps you:
- Debug applications more effectively.
- Know where middleware executes.
- Understand how dependency injection works.
- Understand when service providers are loaded.
- Optimize application performance.

---

# Best Practices

- Keep middleware focused on a single responsibility.
- Keep controllers thin; move business logic to services.
- Avoid performing heavy operations inside middleware.
- Register services using Service Providers.

# Interview Questions

### 1. What is the Laravel Request Lifecycle?

**Answer:**

The Request Lifecycle is the sequence Laravel follows to process an incoming HTTP request, starting from `public/index.php`, passing through bootstrapping, middleware, routing, controllers, and finally returning an HTTP response.

---

### 2. What is Laravel's entry point?

**Answer:**

`public/index.php`

---

### 3. Which file creates the Laravel application?

**Answer:**

`bootstrap/app.php`

---

### 4. What is the role of the HTTP Kernel?

**Answer:**

The HTTP Kernel bootstraps the application, runs middleware, and forwards the request to the router.

---

### 5. At what stage is middleware executed?

**Answer:**

After the application is bootstrapped and before the request reaches the controller.

---

# Key Takeaways

- Every request starts at `public/index.php`.
- `vendor/autoload.php` loads PHP classes automatically.
- `bootstrap/app.php` creates and configures the application.
- The HTTP Kernel bootstraps Laravel.
- Service Providers register and boot services.
- Middleware filters the request.
- The Router finds the matching route.
- The Controller executes business logic.
- Laravel returns an HTTP response to the browser.
