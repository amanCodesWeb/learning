# 0.12 Request vs Response

## Overview

In Laravel, every interaction between the client and the server consists of two parts:

- **Request** → Data sent by the client (browser, mobile app, API client) to the server.
- **Response** → Data returned by the server back to the client.

Laravel provides dedicated classes and helper functions to work with both requests and responses.

---

# Request

A **Request** contains all the information sent by the client.

It may include:

- URL
- HTTP Method (GET, POST, PUT, DELETE)
- Form Data
- Query Parameters
- Headers
- Cookies
- Uploaded Files

Laravel represents it using the `Illuminate\Http\Request` class.

### Example

```php
use Illuminate\Http\Request;

public function store(Request $request)
{
    $name = $request->input('name');

    return $name;
}
```

### Common Request Methods

```php
$request->input('name');

$request->query('search');

$request->all();

$request->only(['name', 'email']);

$request->except('password');

$request->has('email');

$request->file('image');

$request->method();

$request->ip();
```

---

# Response

A **Response** is the data Laravel sends back to the client after processing the request.

Laravel can return:
- View
- JSON
- Redirect
- File Download
- Plain Text

### Return a View

```php
return view('welcome');
```

### Return JSON

```php
return response()->json([
    'success' => true
]);
```

### Redirect

```php
return redirect('/dashboard');
```

### Download File

```php
return response()->download($path);
```

# Best Practices

- Use **Form Requests** for validation.
- Validate user input before processing.
- Return proper HTTP status codes.
- Use JSON responses for APIs.
- Keep controllers focused on handling requests and returning responses.

# Interview Questions

### 1. What is a Request in Laravel?

**Answer:**  
A Request represents the incoming HTTP data sent by the client, including input, headers, files, cookies, and query parameters.

---

### 2. What is a Response?

**Answer:**  
A Response is the data Laravel sends back to the client after processing the request. It can be a view, JSON, redirect, file, or plain text.

---

### 3. How do you access request data?

**Answer:**

```php
$request->input('name');
```

---

### 4. How do you return a JSON response?

**Answer:**

```php
return response()->json([
    'message' => 'Success'
]);
```

---

### 5. What is the difference between a Request and a Response?

| Request | Response |
|---------|----------|
| Sent by the client | Sent by the server |
| Contains user input | Contains processed output |
| Processed by Laravel | Returned to the client |

---

# Key Takeaways

- A **Request** contains data sent by the client.
- A **Response** contains data returned by Laravel.
- Laravel provides the `Request` class and `response()` helper.
- Always validate incoming requests.
- Return appropriate response types and HTTP status codes.
