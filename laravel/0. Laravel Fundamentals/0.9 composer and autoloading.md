# 0.8 Composer & PSR-4 Autoloading

## Overview

**Composer** is PHP's dependency manager. It installs and manages third-party packages, including the Laravel framework.

**PSR-4 Autoloading** is a PHP standard that automatically loads classes based on their namespace and file location, eliminating the need for manual `require` or `include` statements.

---

# Composer

Composer is used to:
- Install Laravel packages
- Manage project dependencies
- Handle autoloading
- Update packages

### Common Commands

Install dependencies:

```bash
composer install
```

Install a package:

```bash
composer require package-name
```

Update dependencies:

```bash
composer update
```

Remove a package:

```bash
composer remove package-name
```

---

# composer.json

The `composer.json` file contains:
- Project information
- PHP version
- Dependencies
- Autoload configuration
- Composer scripts

Example:

```json
{
    "require": {
        "laravel/framework": "^12.0"
    }
}
```

---

# composer.lock

- Stores the exact versions of installed packages.
- Ensures every developer installs the same dependency versions.
- Should always be committed to Git.

---

# PSR-4 Autoloading

PSR-4 maps **namespaces** to directories.

Laravel's default mapping:

```json
"autoload": {
    "psr-4": {
        "App\\": "app/"
    }
}
```

Example:

```php
namespace App\Models;

class User
{
    //
}
```

Laravel automatically loads:

```
app/Models/User.php
```

No manual `require` is needed.

---

# Dump Autoload

If you create new classes manually or change autoload settings, regenerate Composer's autoloader:

```bash
composer dump-autoload
```

---

# Best Practices

- Always use Composer to install packages.
- Do not edit files inside the `vendor/` directory.
- Commit both `composer.json` and `composer.lock`.
- Follow PSR-4 namespace conventions.
- Run `composer dump-autoload` if Composer cannot find a newly created class.

---

# Common Mistakes

- Editing files inside `vendor/`.
- Deleting `composer.lock`.
- Using incorrect namespaces.
- Forgetting to regenerate the autoloader after changing autoload settings.

# Interview Questions

### 1. What is Composer?

**Answer:**  
Composer is PHP's dependency manager. It installs, updates, and manages project dependencies while also handling class autoloading.

---

### 2. What is PSR-4?

**Answer:**  
PSR-4 is a PHP standard for autoloading classes based on namespaces and directory structure.

---

### 3. What is the purpose of `composer.json`?

**Answer:**  
It defines the project's dependencies, autoload configuration, PHP version requirements, and Composer scripts.

---

### 4. What is the purpose of `composer.lock`?

**Answer:**  
It locks the exact versions of installed packages, ensuring consistent installations across all environments.

---

### 5. When do you use `composer dump-autoload`?

**Answer:**  
When you've manually added or moved classes, or changed autoload configuration, and need to regenerate Composer's autoloader.

---

# Key Takeaways

- Composer manages PHP dependencies.
- `composer.json` defines project dependencies.
- `composer.lock` locks dependency versions.
- PSR-4 automatically loads classes based on namespaces.
- Use `composer dump-autoload` to regenerate the autoloader when needed.
