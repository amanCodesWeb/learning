# 0.10 Application Bootstrapping

## Overview

**Application Bootstrapping** is the process of initializing the Laravel application before it starts handling an HTTP request or an Artisan command.

During bootstrapping, Laravel loads the environment, configuration, service providers, and other core services required to run the application.

# Bootstrapping Steps

### 1. Load Composer Autoloader

Laravel loads Composer's autoloader to automatically load classes.

```php
require __DIR__.'/../vendor/autoload.php';
```

---

### 2. Create Application Instance

The `bootstrap/app.php` file creates and configures the Laravel application.

This includes:
- Application instance
- Routing
- Middleware
- Exception handling

---

### 3. Load Environment Variables

Laravel reads the `.env` file and loads environment-specific settings such as:
- Database credentials
- Mail configuration
- Cache driver
- Queue connection

---

### 4. Load Configuration

Laravel loads all configuration files from the `config/` directory and makes them accessible through the `config()` helper.

Example:

```php
config('app.name');
```

---

### 5. Register Facades

Laravel registers facades, providing a simple static interface to services in the Service Container.

Example:

```php
Cache::put('key', 'value');
```

---

### 6. Register Service Providers

All configured Service Providers are registered.
The `register()` method is used to bind services into the Service Container.

---

### 7. Boot Service Providers

After all providers are registered, Laravel calls their `boot()` methods.

This is where providers:
- Register routes
- Register model observers
- Define event listeners
- Share data with views

---

### 8. Application Ready

Once bootstrapping is complete, Laravel begins processing the incoming request or Artisan command.

---

# Important Files

| File | Purpose |
|------|---------|
| `public/index.php` | Application entry point |
| `vendor/autoload.php` | Composer autoloader |
| `bootstrap/app.php` | Creates and configures the application |
| `.env` | Environment variables |
| `config/` | Application configuration |

---

# Best Practices

- Keep `bootstrap/app.php` clean and organized.
- Register services in Service Providers.
- Avoid placing business logic during bootstrapping.
- Store configuration in `config/` and `.env`.

---

# Interview Questions

### 1. What is Application Bootstrapping?

**Answer:**  
Application Bootstrapping is the process of initializing Laravel by loading the environment, configuration, service providers, and core services before handling a request or command.

---

### 2. Which file creates the Laravel application?

**Answer:**

```
bootstrap/app.php
```

---

### 3. What happens during bootstrapping?

**Answer:**

- Composer autoloader is loaded.
- Application instance is created.
- Environment variables are loaded.
- Configuration files are loaded.
- Facades are registered.
- Service Providers are registered and booted.

---

### 4. What is the difference between `register()` and `boot()` in a Service Provider?

**Answer:**

- `register()` → Bind services into the Service Container.
- `boot()` → Execute initialization logic after all services have been registered.

---

### 5. Is bootstrapping executed for every request?

**Answer:**  
Yes. Every HTTP request and every Artisan command goes through Laravel's bootstrapping process before execution.

---

# Key Takeaways

- Bootstrapping prepares Laravel to handle requests and commands.
- The process starts from `public/index.php`.
- `bootstrap/app.php` creates and configures the application.
- Laravel loads `.env`, configuration files, facades, and service providers.
- After bootstrapping, the application is ready to process requests.
