# 4.4 Singleton Binding

## Overview

**Singleton Binding** tells Laravel's Service Container to create **only one instance** of a class and reuse that same instance whenever it is resolved.

```php
$this->app->singleton(
    PaymentService::class,
    PaymentService::class
);
```

## Basic Example

```php
class PaymentService
{
    public function __construct()
    {
        echo "Created";
    }
}
```

Register it:

```php
$this->app->singleton(
    PaymentService::class,
    PaymentService::class
);
```

Now:

```php
$a = app(PaymentService::class);
$b = app(PaymentService::class);
```

Both `$a` and `$b` refer to the **same object instance**.

First resolve  → Create object
Second resolve → Reuse same object
Third resolve  → Reuse same object


## `bind()` vs `singleton()`

```php
$this->app->bind(Service::class, Service::class);
```
Creates a new instance when resolved.

```php
$this->app->singleton(Service::class, Service::class);
```
Reuses the same instance.


| `bind()` | `singleton()` |
|---|---|
| New instance | Same instance |
| No shared instance | One instance per container lifecycle |
| Default choice for many services | Useful for shared services |


## Using a Closure

```php
$this->app->singleton(PaymentService::class, function () {
    return new PaymentService();
});
```

Laravel creates the object once and stores it in the container.

## When to Use Singleton

Useful for services that should be shared, such as:

- API clients
- Configuration managers
- Logging services
- Cache-related services
- Stateless application services

Avoid using singleton just because a class is a service. Use it when sharing the same instance is actually required.

## Where to Define It

Usually inside a Service Provider:

```php
public function register()
{
    $this->app->singleton(
        PaymentService::class,
        PaymentService::class
    );
}
```

## Interview Questions

**Q: What is singleton binding?**  
It registers a class so the Service Container reuses the same instance.

**Q: What is the difference between `bind()` and `singleton()`?**  
`bind()` normally creates a new instance when resolved, while `singleton()` reuses the registered instance.

**Q: Where is singleton binding usually defined?**  
Inside the `register()` method of a Service Provider.

**Q: Does singleton mean one object for the entire server forever?**  
No. It is one instance within the relevant Laravel Service Container lifecycle.
