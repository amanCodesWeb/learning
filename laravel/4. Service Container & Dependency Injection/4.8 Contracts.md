# 4.8 Contracts

## Overview

**Contracts** are Laravel's set of **interfaces** that define how Laravel services should behave.
They provide a clear set of methods that an implementation must follow.

```php
interface PaymentGateway
{
    public function pay();
}
```

Any class implementing it must provide `pay()`.

```php
class StripeGateway implements PaymentGateway
{
    public function pay()
    {
        return "Paid with Stripe";
    }
}
```

## Laravel Contracts

Laravel provides many built-in contracts under:

```text
Illuminate\Contracts
```

Example:

```php
use Illuminate\Contracts\Cache\Repository;
```

Contracts allow your code to depend on an **interface instead of a concrete class**.

## Contracts + Dependency Injection

```php
use Illuminate\Contracts\Cache\Repository;

class ProductService
{
    public function __construct(
        private Repository $cache
    ) {}
}
```

Laravel's Service Container resolves the required implementation.

```text
Class
  ↓
Laravel Contract
  ↓
Service Container
  ↓
Implementation
```

## Why Use Contracts?

- Reduce coupling.
- Make dependencies clear.
- Allow implementations to be replaced.
- Make testing easier.
- Follow dependency inversion principles.

## Contract vs Concrete Class

```php
// Concrete dependency
class ProductService
{
    public function __construct(
        private RedisCache $cache
    ) {}
}
```

```php
// Contract dependency
class ProductService
{
    public function __construct(
        private CacheRepository $cache
    ) {}
}
```

The second approach depends on an abstraction rather than a specific implementation.

## Contracts vs Service Container

**Contract:** Defines what a service should provide.

**Service Container:** Determines which implementation should be provided.

```text
Contract
   ↓
Service Container
   ↓
Implementation
   ↓
Dependency Injection
```

## Important

Not every Laravel class requires you to use a Contract.

Use a Contract when you need an abstraction or want your code to remain independent of a specific implementation.

## Interview Questions

**Q: What are Laravel Contracts?**  
They are interfaces provided by Laravel that define the behavior of Laravel's core services.

**Q: Where are Laravel Contracts located?**

```text
Illuminate\Contracts
```

**Q: Why use Contracts?**  
To depend on abstractions instead of concrete implementations.

**Q: Are Contracts the same as interfaces?**  
Yes. Laravel Contracts are PHP interfaces specifically provided by Laravel.

**Q: How do Contracts work with Dependency Injection?**  
You type-hint the Contract, and Laravel's Service Container resolves the appropriate implementation.

## Quick Revision

```text
Contract = What a service must do
Implementation = How it does it
Container = Which implementation to provide
DI = Gives it to your class
```

**Key Point:** Laravel Contracts let your code depend on **interfaces instead of concrete implementations**.
