# 4.1 What is the Service Container?

## Overview

The **Service Container** is Laravel's system for **managing class dependencies**.

It is mainly used for:

- Dependency Injection
- Resolving classes
- Binding interfaces to implementations
- Managing object creation

> In simple words: **The Service Container knows how to create and provide the objects a class needs.**

## Example

Without the container:

```php
class PaymentService
{
    public function __construct()
    {
        $this->gateway = new StripeGateway();
    }
}
```
This tightly couples PaymentService to StripeGateway.

With Dependency Injection:

```php
class PaymentService
{
    public function __construct(
        private PaymentGateway $gateway
    ) {}
}
```
Laravel's container can resolve and provide the required PaymentGateway.

## Binding

We can tell Laravel which implementation to use:

```php
$this->app->bind(
    PaymentGateway::class,
    StripeGateway::class
);
```
Now:
PaymentGateway → StripeGateway

Bindings are commonly registered in a Service Provider:

```php
public function register(): void
{
    $this->app->bind(
        PaymentGateway::class,
        StripeGateway::class
    );
}
```

## bind() vs singleton()

```php
$this->app->bind(...);
Creates a new instance when resolved.

$this->app->singleton(...);
Creates one instance and reuses it.
```

## Automatic Resolution

Laravel can automatically resolve classes through their constructor:
```php
class OrderService
{
    public function __construct(
        private PaymentService $paymentService
    ) {}
}
```
Laravel builds the required dependency chain automatically when the dependencies can be resolved.


## Service Container vs Dependency Injection

Dependency Injection = technique of providing dependencies to a class.
Service Container = Laravel's system that resolves and provides those dependencies.

## Interview Definition

The Laravel Service Container is a dependency management system that resolves class dependencies and performs dependency injection.
