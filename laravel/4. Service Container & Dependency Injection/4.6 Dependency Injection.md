# 4.6 Dependency Injection

## Overview

**Dependency Injection (DI)** means providing a class with the objects it needs instead of creating those objects inside the class.

```php
class OrderService
{
    public function __construct(
        private PaymentService $payment
    ) {}
}
```

Here, `OrderService` depends on `PaymentService`.

## Without Dependency Injection

```php
class OrderService
{
    public function __construct()
    {
        $this->payment = new PaymentService();
    }
}
```

This creates **tight coupling** because the class decides which implementation to use.

## With Dependency Injection

```php
class OrderService
{
    public function __construct(
        private PaymentService $payment
    ) {}
}
```

Laravel's Service Container can automatically provide `PaymentService`.

```text
OrderService
     ↓
needs PaymentService
     ↓
Service Container
     ↓
injects PaymentService
```

## Types of Dependency Injection

### 1. Constructor Injection

Most commonly used.

```php
class OrderService
{
    public function __construct(
        private PaymentService $payment
    ) {}
}
```

### 2. Method Injection

Dependency is injected into a method.

```php
public function store(PaymentService $payment)
{
    return $payment->process();
}
```

Laravel can resolve the dependency automatically.

## Interface Injection

DI becomes especially useful with interfaces.

```php
interface PaymentGateway
{
    public function pay();
}
```

```php
class OrderService
{
    public function __construct(
        private PaymentGateway $gateway
    ) {}
}
```

Then bind the implementation:

```php
$this->app->bind(
    PaymentGateway::class,
    StripeGateway::class
);
```

Laravel injects `StripeGateway` when `PaymentGateway` is requested.

## Benefits

- Reduces tight coupling.
- Makes code easier to test.
- Makes implementations replaceable.
- Improves maintainability.
- Works naturally with Laravel's Service Container.

## DI vs Service Container

**Dependency Injection:** A programming/design technique for providing dependencies.

**Service Container:** Laravel's system that manages and resolves those dependencies.

```text
Dependency Injection
        ↑
Service Container
        ↓
Creates / Resolves Dependencies
```

## Interview Questions

**Q: What is Dependency Injection?**  
Providing a class with its required dependencies instead of creating them inside the class.

**Q: Which type of DI is most commonly used?**  
Constructor Injection.

**Q: Why is DI useful?**  
It reduces coupling and makes code easier to test and maintain.

**Q: How does Laravel perform DI?**  
Laravel's Service Container resolves and injects type-hinted dependencies.

**Q: DI vs Dependency Inversion?**  
DI is a technique for providing dependencies. Dependency Inversion is a design principle that encourages depending on abstractions rather than concrete implementations.
