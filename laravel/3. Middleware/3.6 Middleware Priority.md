# 3.6 Middleware Priority

## Overview

**Middleware Priority** controls the **execution order** of middleware when multiple middleware are applied to a request.

Order can matter when one middleware depends on another.

## Example

```php
->withMiddleware(function (Middleware $middleware) {
    $middleware->priority([
        StartSession::class,
        Authenticate::class,
        CheckAdmin::class,
    ]);
})
```

Laravel will prioritize middleware in this order.

```text id="m7zq2x"
StartSession
     ↓
Authenticate
     ↓
CheckAdmin
     ↓
Controller
```

## Why Priority Matters

For example, `CheckAdmin` may need an authenticated user.

```text id="y5f8kc"
Authenticate
     ↓
$user available
     ↓
CheckAdmin
     ↓
Check role
```

If `CheckAdmin` runs before authentication, the user may not be available.

## Priority vs Middleware Group

**Group** → defines which middleware are included.

**Priority** → controls the order in which middleware run.

```text id="f3k9qp"
Group
  ↓
auth + admin + verified

Priority
  ↓
auth → verified → admin
```

## Interview Point

**Q: What is Middleware Priority?**
It defines the preferred execution order of middleware when Laravel needs to resolve middleware ordering.

**Q: Why is it important?**
Because some middleware depend on work performed by another middleware.

**Remember:**

```text id="c1v6za"
Middleware A
     ↓
Middleware B
     ↓
Middleware C
     ↓
Controller
```
