# 3.1 Creating Middleware

## Overview

**Middleware** is a layer that sits between the incoming HTTP request and the application's controller.

It can inspect, modify, allow, or reject a request before it reaches the controller.

Middleware can also run code **after** the controller has generated a response.

```text
Request
   ↓
Middleware
   ↓
Controller
   ↓
Response
   ↓
Middleware
   ↓
Client
```

---

## Creating Middleware

Use Artisan:

```bash
php artisan make:middleware CheckAge
```

Laravel creates:

```text
app/Http/Middleware/CheckAge.php
```

---

## Basic Middleware

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class CheckAge
{
    public function handle(
        Request $request,
        Closure $next
    ): Response {
        if ($request->age < 18) {
            abort(403, 'You must be 18 or older.');
        }

        return $next($request);
    }
}
```

The important part is:

```php
return $next($request);
```

It passes the request to the next middleware or, if there are no more middleware, to the controller.

---

## Middleware Flow

```text
Request
   ↓
CheckAge
   ↓
Age >= 18?
   ├── No  → 403 Response
   │
   └── Yes
        ↓
    Next Middleware
        ↓
    Controller
```

If middleware does not call `$next($request)`, the request does not continue.

---

## Middleware Before and After the Request

Middleware can execute code before and after `$next()`.

```php
public function handle(
    Request $request,
    Closure $next
): Response {

    // Before controller
    logger('Request started');

    $response = $next($request);

    // After controller
    logger('Request completed');

    return $response;
}
```

Flow:

```text
Request
   ↓
Before Middleware Code
   ↓
Controller
   ↓
After Middleware Code
   ↓
Response
```

---

## Registering Middleware

Creating a middleware class does not automatically mean it runs on every request.

Laravel middleware can be registered and assigned to routes, route groups, or other middleware configurations.

In current Laravel versions, application middleware configuration is typically handled in:

```text
bootstrap/app.php
```

Example:

```php
->withMiddleware(function (Middleware $middleware) {
    $middleware->alias([
        'check.age' => CheckAge::class,
    ]);
})
```

Now the middleware can be referenced using:

```text
check.age
```

---

## Applying Middleware to a Route

```php
Route::get('/dashboard', function () {
    return 'Dashboard';
})->middleware('check.age');
```

Or on a controller route:

```php
Route::get(
    '/dashboard',
    [DashboardController::class, 'index']
)->middleware('check.age');
```

---

## Applying Middleware to Multiple Routes

Use a route group:

```php
Route::middleware('check.age')->group(function () {

    Route::get('/dashboard', ...);

    Route::get('/profile', ...);

    Route::get('/orders', ...);

});
```

All routes inside the group use the middleware.

---

## Middleware with Parameters

Middleware can receive parameters.

Route:

```php
Route::get('/admin', function () {
    return 'Admin Area';
})->middleware('role:admin');
```

Middleware:

```php
public function handle(
    Request $request,
    Closure $next,
    string $role
): Response {
    if ($request->user()?->role !== $role) {
        abort(403);
    }

    return $next($request);
}
```

Here:

```text
role:admin
    ↓
$role = "admin"
```

Multiple parameters can also be passed:

```php
->middleware('role:admin,manager');
```

```text
Request

```

---

## Middleware vs Controller

### Middleware

Handles concerns that apply **before or around** the controller.

```text
"Is this request allowed to continue?"
```

### Controller

Handles the application's action.

```text
"What should the application do?"
```

Example:

```text
Request
   ↓
Auth Middleware
   ↓
Check user is logged in
   ↓
OrderController
   ↓
Create / show order
```

---

## Middleware vs Form Request

These have different responsibilities.

### Middleware

Usually handles request-wide concerns:

```text
Authentication
Authorization
Logging
Rate limiting
```

### Form Request

Usually handles validation for a specific request:

```text
name → required|string
email → required|email
```

---

## Interview Point

**Q: What is middleware in Laravel?**

**Answer:**
Middleware is a layer that filters or processes HTTP requests before they reach the controller. It can also process the response after the controller has executed.

**Q: What does `$next($request)` do?**

**Answer:**
It passes the request to the next middleware in the pipeline or to the controller if there are no more middleware.

**Q: How do you create middleware?**

```bash
php artisan make:middleware CheckAge
```

**Q: Where is custom middleware configured in current Laravel versions?**

**Answer:**
Application middleware aliases and groups can be configured through `bootstrap/app.php`.

**Remember:**

```text
Request
   ↓
Middleware
   ↓
Allowed?
 ┌─┴─┐
No   Yes
↓     ↓
Stop  Next Middleware
      ↓
   Controller
      ↓
   Response
```
