# 3.2 Global Middleware

## Overview

**Global Middleware** runs on **every HTTP request** in the application.

```text
Request
   ↓
Global Middleware
   ↓
Route Middleware
   ↓
Controller
```

---

## Creating Middleware

```bash
php artisan make:middleware LogRequest
```

Example:

```php
class LogRequest
{
    public function handle(Request $request, Closure $next): Response
    {
        logger($request->path());

        return $next($request);
    }
}
```

---

## Registering Global Middleware

In current Laravel versions, configure it in:

```text
bootstrap/app.php
```

```php
use App\Http\Middleware\LogRequest;

->withMiddleware(function (Middleware $middleware) {
    $middleware->append(LogRequest::class);
})
```

Now it runs for every request.

---

## `append()` and `prepend()`

Add middleware to the global stack:

```php
$middleware->append(LogRequest::class);
```

Add it to the beginning:

```php
$middleware->prepend(LogRequest::class);
```

Order matters when middleware depend on each other.

---

## Global vs Route Middleware

**Global:**

```text
Runs on every request
```

**Route:**

```php
Route::get('/admin', ...)
    ->middleware('admin');
```

Runs only for routes where it is assigned.

---

## Common Uses

Global middleware is suitable for:

* Request logging
* CORS
* Security headers
* Maintenance checks
* Locale detection

Avoid using global middleware for route-specific logic such as admin authorization.

## Interview Point

**Q: What is Global Middleware?**

**Answer:**
Middleware that automatically runs for every HTTP request entering the Laravel application.

**Q: Where is it registered?**

**Answer:**
In current Laravel versions, global middleware is configured in `bootstrap/app.php`.

   ↓
