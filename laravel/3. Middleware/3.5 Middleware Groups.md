# 3.5 Middleware Groups

## Overview

A **Middleware Group** combines multiple middleware under one name.

Instead of assigning middleware individually:

```php
->middleware(['auth', 'verified', 'admin'])
```

You can create a group and use:

```php
->middleware('admin')
```

## Defining a Middleware Group

In current Laravel versions, groups are configured in:

```text
bootstrap/app.php
```

```php
->withMiddleware(function (Middleware $middleware) {
    $middleware->group('admin', [
        'auth',
        'verified',
        CheckAdmin::class,
    ]);
})
```

## Using the Group

```php
Route::middleware('admin')->group(function () {
    Route::get('/dashboard', ...);
    Route::get('/users', ...);
});
```

All routes inside the group use the defined middleware.

## Common Built-in Groups

Laravel commonly provides:

```text
web
api
```

Example:

```php
Route::middleware('web')->group(function () {
    // Web routes
});
```

Middleware groups can contain multiple middleware and are useful for organizing common route behavior.

## Group vs Individual Middleware

```text
Individual:
Route → auth → verified → admin

Group:
Route → admin group
          ↓
       auth
       verified
       admin
```

## Common Uses

* Admin routes
* API routes
* Authenticated routes
* Versioned APIs
* Routes sharing common security rules

## Interview Point

**Q: What is a Middleware Group?**
A named collection of multiple middleware that can be applied to routes together.

**Q: Why use groups?**
To avoid repeating the same middleware list across multiple routes.

**Remember:**

```text
Middleware Group
      ↓
 ┌────┼────┐
auth verified admin
      ↓
   Controller
```
