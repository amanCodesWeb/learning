# 03. Laravel Project Structure

## Overview

A Laravel project has a predefined folder structure.

The structure keeps different parts of the application organized and makes the project easier to maintain.

laravel-project/
│
├── app/
├── bootstrap/
├── config/
├── database/
├── public/
├── resources/
├── routes/
├── storage/
├── tests/
├── vendor/
│
├── .env
├── artisan
├── composer.json
└── package.json


## app

Contains the main application code.

app/
├── Console/
├── Exceptions/
├── Http/
│   ├── Controllers/
│   └── Middleware/
├── Models/
├── Providers/
└── ...

Models : Contains Eloquent models - app/Models/Product.php
```php
class Product extends Model
{
    // Model logic
}
```

Http/Controllers: 
Contains controllers - app/Http/Controllers/ProductController.php

Http/Middleware: 
Contains custom middleware - app/Http/Middleware/CheckAdmin.php

Providers: 
Contains service providers - app/Providers/AppServiceProvider.php


## bootstrap

Contains files required to bootstrap the Laravel application.

    bootstrap/
    └── app.php

`bootstrap/app.php` creates and configures the Laravel application. 
You normally don't put business logic here.


## config

Contains application configuration files.

    config/
    ├── app.php
    ├── database.php
    ├── cache.php
    ├── filesystems.php
    ├── mail.php
    ├── services.php
    └── ...

Example:

    // config/services.php

    'stripe' => [
        'secret' => env('STRIPE_SECRET_KEY'),
    ],

Application code can access it using:

    config('services.stripe.secret');

Use `config()` in application code instead of calling `env()` everywhere.


## database

Contains database-related files.

    database/
    ├── factories/
    ├── migrations/
    └── seeders/

### Migrations

Define database table structure.

    database/migrations/

Example:

    Schema::create('products', function (Blueprint $table) {
        $table->id();
        $table->string('name');
        $table->decimal('price', 10, 2);
        $table->timestamps();
    });

### Seeders

Insert initial or test data.

    database/seeders/

### Factories

Generate fake/test model data.

    database/factories/


## public

Contains files that are directly accessible by the browser.

    public/
    ├── index.php
    └── ...

`public/index.php` is the main entry point for web requests.

In production, the web server should point to the `public`
directory rather than the Laravel project root.


## resources

Contains frontend resources.

    resources/
    ├── views/
    ├── css/
    └── js/

### views

Contains Blade templates.

    resources/views/products/index.blade.php

Example:

    <h1>{{ $product->name }}</h1>

### css

Contains application CSS.

### js

Contains frontend JavaScript.


## routes

Contains route definitions.

    routes/
    ├── web.php
    ├── api.php
    ├── console.php
    └── channels.php

### web.php

Used mainly for web/browser routes.

    Route::get('/products', function () {
        return view('products.index');
    });

### api.php

Used for API routes when API routing is enabled.

    Route::get('/products', function () {
        return Product::all();
    });

### console.php

Used for console commands and scheduling-related definitions.

### channels.php

Used for broadcasting channel authorization.


## storage

Contains files generated or stored by the application.

    storage/
    ├── app/
    ├── framework/
    └── logs/

### app

Contains application-generated files.

### framework

Contains framework-generated files such as cache and compiled files.

### logs

Contains application logs.

Example:

    storage/logs/laravel.log


## tests

Contains automated tests.

    tests/
    ├── Feature/
    └── Unit/

### Feature

Tests complete application features or request flows.

### Unit

Tests individual pieces of application logic.


## vendor

Contains Composer dependencies.

    vendor/
    ├── laravel/
    ├── symfony/
    └── ...

This directory is generated by Composer.

Do not manually edit files inside `vendor/`.

It is normally excluded from Git and recreated using:

    composer install


## .env

Contains environment-specific configuration.

Example:

    APP_ENV=local
    APP_DEBUG=true

    DB_HOST=127.0.0.1
    DB_DATABASE=shop
    DB_USERNAME=root
    DB_PASSWORD=secret

    STRIPE_SECRET_KEY=xxxx

Sensitive values such as passwords and API keys should not be committed to the repository.


## artisan

`artisan` is Laravel's command-line entry point.

Examples:

    php artisan serve
    php artisan migrate
    php artisan route:list
    php artisan make:model Product
    php artisan make:controller ProductController


## composer.json

Defines PHP dependencies and Composer configuration.

Example:

    {
        "require": {
            "laravel/framework": "^12.0"
        }
    }

Composer uses this file to install and manage PHP packages.


## package.json

Defines frontend JavaScript dependencies and scripts.

It is commonly used with tools such as Vite.

Example:

    {
        "scripts": {
            "dev": "vite",
            "build": "vite build"
        }
    }


## Request Flow

A basic Laravel request can be understood through the project structure:

    Browser
       ↓
    public/index.php
       ↓
    bootstrap/app.php
       ↓
    Middleware
       ↓
    routes/web.php
       ↓
    Controller
       ↓
    Model / Service
       ↓
    Database
       ↓
    Response
       ↓
    Browser


## What You Must Know

You don't need to memorize every Laravel folder.

Know the purpose of these:

    app/           → Application code
    app/Models/    → Eloquent models
    app/Http/      → Controllers & middleware
    config/        → Configuration
    database/      → Migrations, seeders, factories
    public/        → Public entry point
    resources/     → Blade views, CSS, JS
    routes/        → Route definitions
    storage/       → Logs, cache, generated files
    tests/         → Automated tests
    vendor/        → Composer dependencies
    .env           → Environment-specific values
    artisan        → Laravel CLI


## Quick Reference

    Model       → app/Models
    Controller  → app/Http/Controllers
    Middleware  → app/Http/Middleware
    Provider    → app/Providers
    Route       → routes/
    View        → resources/views
    Migration   → database/migrations
    Seeder      → database/seeders
    Config      → config/
    Logs        → storage/logs
    Dependencies→ vendor/


## Remember

The most important folders are:

    app/        → Application logic
    config/     → Configuration
    database/   → Database structure and data
    public/     → Application entry point
    resources/  → Frontend and views
    routes/     → Routes
    storage/    → Generated files and logs
    tests/      → Tests
    vendor/     → Composer dependencies

The main rule to remember:

    Where does my code go?

    Model       → app/Models
    Controller  → app/Http/Controllers
    Middleware  → app/Http/Middleware
    Route       → routes/
    View        → resources/views
    Migration   → database/migrations
    Config      → config/
