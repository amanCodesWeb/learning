# INNER JOIN — Matching Rows in Both Tables

`INNER JOIN` returns only rows where the join condition matches in **both** tables. It's the most common join type.

---

## Visual Representation

```
TABLE A (users)          TABLE B (orders)          INNER JOIN RESULT
┌────┬────────┐          ┌────┬────────┬────────┐  ┌────┬────────┬────────┐
│ id │ name   │          │ id │ user_id │ total  │  │ id │ name   │ total  │
├────┼────────┤          ├────┼─────────┼────────┤  ├────┼────────┼────────┤
│ 1  │ Alice  │    ──┐   │ 101│ 1       │ 99.99  │  │ 1  │ Alice  │ 99.99  │
│ 2  │ Bob    │  ──┐ │   │ 102│ 1       │ 149.50 │  │ 1  │ Alice  │ 149.50 │
│ 3  │ Carol  │  │ └─┼──►│ 103│ 2       │ 75.00  │  │ 2  │ Bob    │ 75.00  │
│ 4  │ Dave   │  │    │   │ 104│ 5       │ 200.00 │  └────┴────────┴────────┘
└────┴────────┘  │    │   └────┴────────┴────────┘
   (no orders)  │    │      (user 5 doesn't exist)
                └────┘
```

**Result**: Only Alice (2 orders) and Bob (1 order). Carol and Dave excluded (no orders). Order 104 excluded (user 5 doesn't exist).

---

## Syntax

```sql
SELECT columns
FROM table_a AS a
INNER JOIN table_b AS b
    ON a.common_column = b.common_column;

-- INNER keyword is optional (JOIN = INNER JOIN)
FROM table_a AS a
JOIN table_b AS b ON a.id = b.a_id;
```

---

## Basic Example

```sql
-- Users with their orders
SELECT
    u.id AS user_id
    , u.full_name
    , u.email
    , o.id AS order_id
    , o.total
    , o.status
    , o.created_at AS order_date
FROM users AS u
INNER JOIN orders AS o
    ON u.id = o.user_id
ORDER BY u.full_name, o.created_at DESC;
```

## Multiple JOINs

```sql
-- Users → Orders → Order Items → Products
SELECT
    u.full_name AS customer
    , o.id AS order_id
    , o.created_at AS order_date
    , oi.quantity
    , p.name AS product
    , p.brand
    , oi.unit_price
    , oi.total AS line_total
FROM users AS u
INNER JOIN orders AS o ON u.id = o.user_id
INNER JOIN order_items AS oi ON o.id = oi.order_id
INNER JOIN products AS p ON oi.product_id = p.id
WHERE o.status = 'delivered'
ORDER BY o.created_at DESC;
```

## Join Conditions Beyond Equality

```sql
-- Range join: orders within date range of a promotion
SELECT o.*, p.name AS promo_name
FROM orders AS o
INNER JOIN promotions AS p
    ON o.created_at BETWEEN p.start_date AND p.end_date
    AND o.total >= p.min_order_value;

-- Composite key join
SELECT *
FROM order_items AS oi
INNER JOIN product_variants AS pv
    ON oi.product_id = pv.product_id
    AND oi.variant_id = pv.variant_id;
```

## Filtering: WHERE vs ON

```sql
-- ⚠️ Different results!

-- WHERE filters AFTER join (removes rows from result)
SELECT u.name, o.total
FROM users u
INNER JOIN orders o ON u.id = o.user_id
WHERE o.status = 'delivered';  -- Only delivered orders in result

-- ON filters DURING join (affects which rows join)
-- For INNER JOIN, same result as WHERE
-- But for LEFT JOIN, VERY different!

-- Multiple conditions in ON
SELECT u.name, o.total
FROM users u
INNER JOIN orders o
    ON u.id = o.user_id
    AND o.status = 'delivered'  -- Part of join condition
    AND o.created_at >= '2024-01-01';
```

## Performance: Join Order & Indexes

```sql
-- Database optimizes join order automatically
-- But you can help with indexes:

-- Essential: index on foreign key columns
CREATE INDEX idx_orders_user_id ON orders(user_id);
CREATE INDEX idx_order_items_order_id ON order_items(order_id);
CREATE INDEX idx_order_items_product_id ON order_items(product_id);

-- Composite index for filtered joins
CREATE INDEX idx_orders_user_status_date
    ON orders(user_id, status, created_at);
```

### Join Algorithms

| Algorithm | When Used | Complexity |
|-----------|-----------|------------|
| **Nested Loop** | Small tables, no index | O(M × N) |
| **Hash Join** | Large tables, no useful index | O(M + N) |
| **Merge Join** | Both tables sorted on join key | O(M + N) |

```sql
-- Force join order (MySQL)
SELECT /*+ JOIN_ORDER(u, o, oi) */ ...
FROM users u JOIN orders o ... JOIN order_items oi ...

-- PostgreSQL: join_collapse_limit, from_collapse_limit control planning
```

## Common Patterns

### 1. Many-to-Many (Junction Table)
```sql
-- Products ↔ Categories
SELECT p.name, c.name AS category
FROM products AS p
INNER JOIN product_categories AS pc ON p.id = pc.product_id
INNER JOIN categories AS c ON pc.category_id = c.id;
```

### 2. Self-Join (Hierarchy)
```sql
-- Employee → Manager
SELECT
    e.name AS employee
    , m.name AS manager
FROM employees AS e
INNER JOIN employees AS m ON e.manager_id = m.id;
```

### 3. Latest Record Per Group
```sql
-- Latest order per user (using derived table)
SELECT u.*, o.*
FROM users AS u
INNER JOIN (
    SELECT user_id, MAX(created_at) AS max_date
    FROM orders
    GROUP BY user_id
) AS latest ON u.id = latest.user_id
INNER JOIN orders AS o
    ON latest.user_id = o.user_id AND latest.max_date = o.created_at;
```
