# LEFT JOIN — Keep All Left Table Rows

`LEFT JOIN` returns **all rows from the left table**, plus matching rows from the right table. Non-matching right columns become `NULL`.

---

## Visual Representation

```
TABLE A (users)          TABLE B (orders)          LEFT JOIN RESULT
┌────┬────────┐          ┌────┬────────┬────────┐  ┌────┬────────┬────────┐
│ id │ name   │          │ id │ user_id │ total  │  │ id │ name   │ total  │
├────┼────────┤          ├────┼─────────┼────────┤  ├────┼────────┼────────┤
│ 1  │ Alice  │    ──┐   │ 101│ 1       │ 99.99  │  │ 1  │ Alice  │ 99.99  │
│ 2  │ Bob    │  ──┐ │   │ 102│ 1       │ 149.50 │  │ 1  │ Alice  │ 149.50 │
│ 3  │ Carol  │  │ └─┼──►│ 103│ 2       │ 75.00  │  │ 2  │ Bob    │ 75.00  │
│ 4  │ Dave   │  │    │   │ 104│ 5       │ 200.00 │  │ 3  │ Carol  │ NULL   │
└────┴────────┘  │    │   └────┴────────┴────────┘  │ 4  │ Dave   │ NULL   │
   (no orders)  │    │      (user 5 doesn't exist)   └────┴────────┴────────┘
                └────┘
```

**Result**: All 4 users. Alice (2 orders), Bob (1 order), Carol (NULL - no orders), Dave (NULL - no orders). Order 104 excluded (no matching user).

---

## Syntax

```sql
SELECT columns
FROM left_table AS l
LEFT JOIN right_table AS r
    ON l.common_column = r.common_column;

-- LEFT OUTER JOIN = LEFT JOIN (OUTER is optional)
```

---

## Basic Example

```sql
-- All users, with their order count (including zero)
SELECT
    u.id
    , u.full_name
    , u.email
    , COUNT(o.id) AS order_count
    , COALESCE(SUM(o.total), 0) AS total_spent
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
GROUP BY u.id, u.full_name, u.email
ORDER BY total_spent DESC;
```

---

## Critical: WHERE vs ON with LEFT JOIN

This is the **most common LEFT JOIN mistake**:

```sql
-- ❌ WRONG: WHERE filters AFTER join, turns LEFT JOIN into INNER JOIN
SELECT u.name, o.total
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.status = 'delivered';  -- Removes Carol & Dave (o.status is NULL)

-- ✅ CORRECT: Filter in ON clause
SELECT u.name, o.total
FROM users u
LEFT JOIN orders o
    ON u.id = o.user_id
    AND o.status = 'delivered';  -- Keeps Carol & Dave, o.total = NULL
```

### Why This Matters

| Clause | When Applied | Effect on LEFT JOIN |
|--------|--------------|---------------------|
| `ON` | During join | Non-matching right rows kept as NULL |
| `WHERE` | After join | Filters out NULLs from right table = INNER JOIN |

## Finding "Missing" Data (Anti-Join Pattern)

```sql
-- Users who NEVER ordered
SELECT u.*
FROM users AS u
LEFT JOIN orders AS o ON u.id = o.user_id
WHERE o.id IS NULL;  -- No matching order

-- Products never ordered
SELECT p.*
FROM products AS p
LEFT JOIN order_items AS oi ON p.id = oi.product_id
WHERE oi.id IS NULL;

-- Inactive users (no orders in last 90 days)
SELECT u.*
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
    AND o.created_at >= DATE_SUB(NOW(), INTERVAL 90 DAY)
WHERE o.id IS NULL;
```

## Multiple LEFT JOINs

```sql
-- All users, their orders, and order items (even if no orders/items)
SELECT
    u.full_name
    , o.id AS order_id
    , o.status
    , p.name AS product
    , oi.quantity
FROM users AS u
LEFT JOIN orders AS o ON u.id = o.user_id
LEFT JOIN order_items AS oi ON o.id = oi.order_id
LEFT JOIN products AS p ON oi.product_id = p.id;
```

> **Rule**: Once you `LEFT JOIN`, continue `LEFT JOIN`ing downstream tables. An `INNER JOIN` after a `LEFT JOIN` cancels the outer effect.

## LEFT JOIN with Aggregations

```sql
-- User stats (handles zero orders correctly)
SELECT
    u.id
    , u.full_name
    , COUNT(o.id) AS order_count              -- 0 for no orders
    , COALESCE(SUM(o.total), 0) AS revenue    -- 0 not NULL
    , COALESCE(AVG(o.total), 0) AS avg_order
    , MAX(o.created_at) AS last_order_date    -- NULL if no orders
FROM users AS u
LEFT JOIN orders AS o ON u.id = o.user_id
GROUP BY u.id, u.full_name;
```

---

## Conditional Aggregation with LEFT JOIN

```sql
-- Order status breakdown per user
SELECT
    u.full_name
    , COUNT(o.id) AS total_orders
    , COUNT(CASE WHEN o.status = 'delivered' THEN 1 END) AS delivered
    , COUNT(CASE WHEN o.status = 'cancelled' THEN 1 END) AS cancelled
    , COUNT(CASE WHEN o.status IN ('pending','paid') THEN 1 END) AS pending
FROM users AS u
LEFT JOIN orders AS o ON u.id = o.user_id
GROUP BY u.id, u.full_name;
```

## Performance Notes

```sql
-- Index on foreign key (critical for LEFT JOIN performance)
CREATE INDEX idx_orders_user_id ON orders(user_id);

-- Composite index for filtered LEFT JOIN
CREATE INDEX idx_orders_user_status
    ON orders(user_id, status);

-- For "missing data" queries, consider NOT EXISTS (sometimes faster)
SELECT u.* FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```
