# Basic Syntax & Conventions

Writing clean, readable SQL is a skill. Consistent style prevents bugs, makes code review easier, and helps your future self.

---

## Core Syntax Rules

### 1. Keywords: UPPERCASE
```sql
-- ✅ Good
SELECT id, name, email
FROM users
WHERE is_active = TRUE
ORDER BY created_at DESC;

-- ❌ Hard to read
select id, name, email from users where is_active = true order by created_at desc;
```

### 2. Identifiers: snake_case, lowercase
```sql
-- ✅ Good
CREATE TABLE user_profiles (
    user_id BIGINT PRIMARY KEY,
    full_name VARCHAR(100),
    date_of_birth DATE,
    is_public BOOLEAN DEFAULT FALSE
);

-- ❌ Inconsistent
CREATE TABLE UserProfiles (
    UserID BIGINT PRIMARY KEY,
    FullName VARCHAR(100),
    DateOfBirth DATE,
    IsPublic BOOLEAN DEFAULT FALSE
);
```

### 3. Indentation & Line Breaks
```sql
-- ✅ Good: one clause per line, aligned
SELECT
    u.id,
    u.email,
    u.full_name,
    COUNT(o.id) AS order_count,
    COALESCE(SUM(o.total), 0) AS lifetime_value
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
WHERE u.is_active = TRUE
    AND u.created_at >= '2024-01-01'
GROUP BY u.id, u.email, u.full_name
HAVING COUNT(o.id) > 0
ORDER BY lifetime_value DESC
LIMIT 20;

-- ❌ All on one line
SELECT u.id, u.email, u.full_name, COUNT(o.id) AS order_count FROM users AS u LEFT JOIN orders AS o ON u.id = o.user_id WHERE u.is_active = TRUE AND u.created_at >= '2024-01-01' GROUP BY u.id, u.email, u.full_name HAVING COUNT(o.id) > 0 ORDER BY lifetime_value DESC LIMIT 20;
```

### 4. Commas: Leading (Easier to Comment/Reorder)
```sql
-- ✅ Preferred: leading commas
SELECT
    id
    , email
    , full_name
    , created_at
FROM users;

-- Alternative: trailing commas (also fine, pick one style)
SELECT
    id,
    email,
    full_name,
    created_at,
FROM users;  -- Note: trailing comma after last column works in some DBs
```

## Naming Conventions

| Object | Convention | Examples |
|--------|------------|----------|
| **Database** | snake_case, singular | `ecommerce`, `analytics_warehouse` |
| **Table** | snake_case, **plural** | `users`, `order_items`, `product_categories` |
| **Column** | snake_case, singular | `user_id`, `full_name`, `created_at`, `is_active` |
| **Primary Key** | `id` or `table_id` | `id`, `user_id` (in child tables) |
| **Foreign Key** | `referenced_table_id` | `user_id`, `category_id`, `order_id` |
| **Index** | `idx_table_column(s)` | `idx_users_email`, `idx_orders_user_status` |
| **Unique Constraint** | `uk_table_column(s)` | `uk_users_email`, `uk_products_sku` |
| **Foreign Key Constraint** | `fk_table_referenced` | `fk_orders_user`, `fk_order_items_product` |
| **Check Constraint** | `chk_table_condition` | `chk_products_price_positive` |
| **View** | `v_table_purpose` | `v_active_users`, `v_monthly_sales` |
| **Stored Procedure** | `sp_purpose` | `sp_calculate_commission` |
| **Function** | `fn_purpose` | `fn_format_currency` |
| **Trigger** | `trg_table_action` | `trg_users_audit_insert` |

## Reserved Words & Quoting

Some names are reserved (SELECT, FROM, WHERE, ORDER, GROUP, USER, GROUP, etc.). Avoid them, or quote:

```sql
-- ❌ 'order' is reserved
CREATE TABLE order (id INT);  -- ERROR in most DBs

-- ✅ Quote if you must use reserved word
CREATE TABLE "order" (id INT);           -- Standard SQL (double quotes)
CREATE TABLE `order` (id INT);           -- MySQL (backticks)
CREATE TABLE [order] (id INT);           -- SQL Server (brackets)

-- Better: just don't use reserved words
CREATE TABLE orders (id INT);            -- Use plural
CREATE TABLE user_order (id INT);        -- Or prefix
```

> **Rule**: Never use reserved words as identifiers. It's not worth the quoting hassle.

## Comments

```sql
-- Single line comment (standard SQL)
-- This filters to active users only
SELECT * FROM users WHERE is_active = TRUE;

-- Inline comment
SELECT id, email  -- only need these columns
FROM users;

-- Block comment (standard SQL)
/*
 * Monthly active users report
 * Runs on 1st of each month
 * Excludes test accounts (email like '%@test.%')
 */
SELECT COUNT(DISTINCT user_id)
FROM events
WHERE event_date >= DATE_TRUNC('month', CURRENT_DATE)
    AND user_id NOT IN (SELECT id FROM users WHERE email LIKE '%@test.%');
```

> **MySQL also supports `#` for single-line comments** — but `--` is standard and portable.

## String Literals

```sql
-- Standard SQL: single quotes only
SELECT 'Hello, world!';
SELECT 'It''s working';          -- Escape single quote by doubling

-- MySQL also supports double quotes (if ANSI_QUOTES off)
SELECT "Hello";                  -- Avoid: not portable

-- PostgreSQL: dollar quoting for complex strings
SELECT $$It's "quoted" and 'works'$$;
SELECT $tag$Multi-line
with 'quotes' and "double quotes"$tag$;
```

## Numeric Literals

```sql
-- Integers
SELECT 42, -10, +5;

-- Decimals
SELECT 3.14, -0.5, +100.00;

-- Scientific notation
SELECT 1e3, 2.5E-2;   -- 1000, 0.025

-- Hex (MySQL/PostgreSQL)
SELECT x'FF', 0xFF;   -- 255

-- Bit literals (MySQL)
SELECT b'1010';       -- 10
```

## Date/Time Literals

```sql
-- Standard ISO format (works everywhere)
SELECT DATE '2024-01-15';
SELECT TIME '14:30:00';
SELECT TIMESTAMP '2024-01-15 14:30:00';

-- MySQL also accepts strings (implicit cast)
SELECT '2024-01-15';           -- DATE context
SELECT '2024-01-15 14:30:00';  -- DATETIME context

-- Interval literals (standard SQL)
SELECT INTERVAL '7' DAY;
SELECT INTERVAL '3' MONTH;
SELECT INTERVAL '1 12:30' DAY TO MINUTE;  -- 1 day 12 hours 30 min
```

## NULL Handling

```sql
-- NULL = unknown, not zero, not empty string
-- Any comparison with NULL = UNKNOWN (not TRUE, not FALSE)

-- ❌ Wrong
WHERE column = NULL;      -- Never matches!
WHERE column != NULL;     -- Never matches!

-- ✅ Correct
WHERE column IS NULL;
WHERE column IS NOT NULL;

-- NULL-safe equality (MySQL/PostgreSQL)
WHERE column <=> NULL;    -- TRUE if both NULL
WHERE column <=> 'value'; -- Normal comparison

-- COALESCE: first non-NULL
SELECT COALESCE(phone, email, 'No contact') AS contact;

-- NULLIF: return NULL if equal
SELECT NULLIF(empty_string, '');  -- '' becomes NULL
```

## Boolean Logic

```sql
-- AND has higher precedence than OR
-- ✅ Use parentheses for clarity
WHERE (status = 'active' OR status = 'pending')
    AND created_at >= '2024-01-01'
    AND is_deleted = FALSE;

-- IN / NOT IN (cleaner than multiple OR)
WHERE status IN ('active', 'pending', 'trial');
WHERE category_id NOT IN (1, 5, 9);

-- BETWEEN (inclusive)
WHERE price BETWEEN 10.00 AND 100.00;
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';

-- LIKE patterns
WHERE email LIKE '%@gmail.com';      -- Ends with
WHERE name LIKE 'J%';                -- Starts with J
WHERE sku LIKE 'PRD-___-____';       -- Underscore = single char

-- Regular expressions
-- MySQL: REGEXP
WHERE email REGEXP '^[^@]+@[^@]+\.[^@]+$';
-- PostgreSQL: ~ (case-sensitive), ~* (case-insensitive)
WHERE email ~* '^[^@]+@[^@]+\.[^@]+$';
```

## Semicolons

```sql
-- ✅ Always terminate statements
SELECT * FROM users;
INSERT INTO users (email) VALUES ('test@example.com');

-- Some tools allow omitting on last statement, but don't rely on it
-- In scripts: always use semicolons
```

## Common Style Guide Summary

```sql
-- 1. UPPERCASE keywords
-- 2. lowercase snake_case identifiers
-- 3. One clause per line
-- 4. 4-space indentation
-- 5. Leading commas in column lists
-- 6. Meaningful aliases (AS keyword optional but clear)
-- 7. Explicit column lists (never SELECT * in production)
-- 8. Table aliases: 1-2 letters, related to name
-- 9. Constraint names: prefix with type (pk_, fk_, uk_, idx_, chk_)
-- 10. Comments for "why", not "what"
```

## Practice Exercise

### Reformat This Query
```sql
-- Original (hard to read)
select u.id,u.name,count(o.id) as orders,sum(o.total) as revenue from users u left join orders o on u.id=o.user_id where u.active=1 and u.created>'2024-01-01' group by u.id,u.name having count(o.id)>0 order by revenue desc limit 10;
```

### Solution
```sql
SELECT
    u.id
    , u.name
    , COUNT(o.id) AS orders
    , SUM(o.total) AS revenue
FROM users AS u
LEFT JOIN orders AS o
    ON u.id = o.user_id
WHERE u.active = TRUE
    AND u.created > '2024-01-01'
GROUP BY u.id, u.name
HAVING COUNT(o.id) > 0
ORDER BY revenue DESC
LIMIT 10;
```
