# Data Types

Every column in a table has a **data type** that defines what kind of values it can store. Choosing the right type affects storage, performance, and data integrity.

---

## Numeric Types

| Type | Range / Precision | Storage | Use Case |
|------|-------------------|---------|----------|
| `TINYINT` | -128 to 127 (signed), 0 to 255 (unsigned) | 1 byte | Flags, small counters, boolean-like |
| `SMALLINT` | -32,768 to 32,767 | 2 bytes | Small integers, ages, years |
| `INT` / `INTEGER` | -2.1B to 2.1B | 4 bytes | **Default for IDs, counts, quantities** |
| `BIGINT` | -9 quintillion to 9 quintillion | 8 bytes | Large IDs, timestamps (ms), high-volume counters |
| `DECIMAL(p,s)` / `NUMERIC(p,s)` | Exact, up to 65 digits | Variable | **Money, prices, precise calculations** |
| `FLOAT` / `DOUBLE` | Approximate, 7 / 15 digits | 4 / 8 bytes | Scientific measurements, NOT for money |

> **Critical Rule**: **Never use `FLOAT`/`DOUBLE` for money.** Use `DECIMAL(10,2)` for prices (10 digits total, 2 after decimal).

```sql
-- Price column: up to 99,999,999.99
price DECIMAL(10, 2)

-- Percentage with 4 decimal places
tax_rate DECIMAL(5, 4)

-- High-precision scientific
measurement DOUBLE PRECISION
```

## String Types

| Type | Max Length | Storage | Use Case |
|------|------------|---------|----------|
| `CHAR(n)` | Fixed n (0-255) | n bytes | Fixed-length codes (ISO country codes: `CHAR(2)`) |
| `VARCHAR(n)` | Variable up to n (0-65,535) | Length + 1-2 bytes | **Names, emails, addresses, short text** |
| `TEXT` | 65,535 | Length + 2 bytes | Longer descriptions, content |
| `LONGTEXT` | 4GB | Length + 4 bytes | Very large documents |

> **Best Practice**: Default to `VARCHAR(255)` for most strings. Use `TEXT` only when you need >255 chars.

```sql
-- Good choices
email VARCHAR(255)        -- RFC 5321 max is 254
username VARCHAR(50)
slug VARCHAR(100)         -- URL-friendly identifiers
description TEXT          -- Product descriptions, bios
content LONGTEXT          -- Blog posts, articles

-- Fixed length - only when truly fixed
country_code CHAR(2)      -- 'US', 'GB', 'JP'
currency_code CHAR(3)     -- 'USD', 'EUR', 'JPY'
hash CHAR(64)             -- SHA-256 hex output
```

## Date & Time Types

| Type | Range | Storage | Format |
|------|-------|---------|--------|
| `DATE` | 1000-01-01 to 9999-12-31 | 3 bytes | `YYYY-MM-DD` |
| `TIME` | -838:59:59 to 838:59:59 | 3 bytes | `HH:MM:SS` |
| `DATETIME` | 1000-01-01 to 9999-12-31 | 8 bytes | `YYYY-MM-DD HH:MM:SS` |
| `TIMESTAMP` | 1970-01-01 to 2038-01-19 | 4 bytes | `YYYY-MM-DD HH:MM:SS` (UTC) |
| `YEAR` | 1901 to 2155 | 1 byte | `YYYY` |

> **`DATETIME` vs `TIMESTAMP`**:
> - `TIMESTAMP` auto-converts to/from UTC (stores UTC, displays in session timezone)
> - `DATETIME` stores literally what you give it (no timezone conversion)
> - `TIMESTAMP` range ends in 2038 (Year 2038 problem)
> - **Use `DATETIME` for most apps; `TIMESTAMP` for audit logs, created_at/updated_at**

```sql
-- Birth date (no time component)
birth_date DATE

-- Appointment with time
appointment_at DATETIME

-- Auto-set on insert/update (MySQL/PostgreSQL)
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP

-- PostgreSQL specific (preferred)
created_at TIMESTAMPTZ DEFAULT NOW()
```

## Boolean & Special Types

| Type | Values | Storage | Notes |
|------|--------|---------|-------|
| `BOOLEAN` / `BOOL` | `TRUE`/`FALSE` (stored as 1/0) | 1 byte | Alias for `TINYINT(1)` in MySQL |
| `ENUM('a','b','c')` | One of listed values | 1-2 bytes | **Use sparingly** — schema change to add values |
| `SET('a','b','c')` | Zero or more of listed | 1-8 bytes | Rarely used |
| `JSON` | Valid JSON document | Variable | PostgreSQL: `JSONB` (binary, indexed); MySQL: `JSON` |
| `UUID` | 128-bit unique identifier | 16 bytes | PostgreSQL native; MySQL: `CHAR(36)` or `BINARY(16)` |

```sql
-- Boolean (standard SQL)
is_active BOOLEAN DEFAULT TRUE
is_deleted BOOLEAN DEFAULT FALSE

-- Enum - only for truly fixed sets
status ENUM('pending', 'paid', 'shipped', 'delivered', 'cancelled')

-- JSON - flexible attributes
metadata JSON        -- MySQL
metadata JSONB       -- PostgreSQL (indexable!)

-- UUID (PostgreSQL)
id UUID PRIMARY KEY DEFAULT gen_random_uuid()
```

## Type Selection Checklist

| Question | Decision |
|----------|----------|
| Is it money? | `DECIMAL(10,2)` |
| Is it a whole number (ID, count)? | `INT` or `BIGINT` |
| Is it a short string (<255)? | `VARCHAR(255)` |
| Is it long text? | `TEXT` |
| Is it a date only? | `DATE` |
| Is it date + time? | `DATETIME` (or `TIMESTAMPTZ` in PG) |
| Is it true/false? | `BOOLEAN` |
| Is it a fixed set of 2-10 values? | Consider `ENUM` or lookup table |
| Is it flexible key-value data? | `JSON`/`JSONB` |

## Common Mistakes

| Mistake | Why It's Bad | Fix |
|---------|--------------|-----|
| `VARCHAR(1000)` for everything | Wastes space, no constraint | Right-size your columns |
| `FLOAT` for prices | Rounding errors ($19.99 → $19.989999) | `DECIMAL(10,2)` |
| `INT` for phone numbers | Loses leading zeros, can't store + | `VARCHAR(20)` |
| `TIMESTAMP` for birth dates | 2038 cutoff, timezone confusion | `DATE` |
| No `NOT NULL` on required fields | Allows bad data | Add constraints |

## Practice Exercises

### Exercise 1: Choose the Right Type
For each column, pick the best type:

1. User's full name → `VARCHAR(100)`
2. Product price in USD → `DECIMAL(10,2)`
3. Quantity in stock → `INT`
4. Article content → `TEXT`
5. Order placed timestamp → `DATETIME` (or `TIMESTAMPTZ`)
6. Country code (ISO 3166) → `CHAR(2)`
7. Is the user an admin? → `BOOLEAN`
8. Tags for a blog post (multiple) → `JSON` or separate table

### Exercise 2: Create Table
```sql
-- Write CREATE TABLE for an e-commerce product
CREATE TABLE products (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    sku VARCHAR(50) NOT NULL UNIQUE,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    price DECIMAL(10,2) NOT NULL,
    cost DECIMAL(10,2),
    weight_kg DECIMAL(6,3),
    category_id INT,
    is_active BOOLEAN DEFAULT TRUE,
    launch_date DATE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```
