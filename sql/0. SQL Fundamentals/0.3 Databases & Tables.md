# Databases & Tables

Understanding how to create, organize, and manage databases and tables is the foundation of working with SQL.

---

## Database vs Table vs Schema

```
┌─────────────────────────────────────────────────────────────┐
│                    DATABASE (e.g., ecommerce)                │
│  ┌─────────────────┐  ┌─────────────────┐  ┌─────────────┐  │
│  │  SCHEMA: public │  │  SCHEMA: admin  │  │  SCHEMA: ...│  │
│  │  ┌───────────┐  │  │  ┌───────────┐  │  │             │  │
│  │  │ TABLES    │  │  │  │ TABLES    │  │  │             │  │
│  │  │ users     │  │  │  │ orders    │  │  │             │  │
│  │  │ products  │  │  │  │ logs      │  │  │             │  │
│  │  │ orders    │  │  │  │ settings  │  │  │             │  │
│  │  └───────────┘  │  │  └───────────┘  │  │             │  │
│  └─────────────────┘  └─────────────────┘  └─────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

- **Database** = Top-level container (separate apps usually use separate databases)
- **Schema** = Namespace within a database (PostgreSQL default: `public`; MySQL: schema = database)
- **Table** = Actual data storage (rows + columns)

## Creating a Database

```sql
-- Basic create
CREATE DATABASE ecommerce;

-- With character set (MySQL) / encoding (PostgreSQL)
CREATE DATABASE ecommerce
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- PostgreSQL: specify owner, template, encoding
CREATE DATABASE ecommerce
  OWNER app_user
  ENCODING 'UTF8'
  LC_COLLATE 'en_US.UTF-8'
  LC_CTYPE 'en_US.UTF-8'
  TEMPLATE template0;

-- Only if not exists (idempotent - safe for scripts)
CREATE DATABASE IF NOT EXISTS ecommerce;
```

> **Character Sets**: Always use `utf8mb4` (MySQL) or `UTF8` (PostgreSQL) to support emojis and all Unicode. Old `utf8` in MySQL is broken (max 3 bytes).

## Creating Tables

### Basic Syntax

```sql
CREATE TABLE table_name (
    column1 data_type constraints,
    column2 data_type constraints,
    column3 data_type constraints,
    -- table-level constraints
    CONSTRAINT constraint_name constraint_definition
);
```

### Complete Example: Users Table

```sql
CREATE TABLE users (
    -- Primary key: unique identifier, auto-increment
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

    -- Required fields with sensible lengths
    email VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,  -- Never store plain passwords!
    full_name VARCHAR(100) NOT NULL,

    -- Optional fields
    phone VARCHAR(20),
    birth_date DATE,
    avatar_url VARCHAR(500),

    -- Status & metadata
    is_active BOOLEAN DEFAULT TRUE,
    is_verified BOOLEAN DEFAULT FALSE,
    role ENUM('user', 'admin', 'moderator') DEFAULT 'user',

    -- Timestamps (auto-managed)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted_at DATETIME NULL,  -- For soft deletes

    -- Constraints
    PRIMARY KEY (id),
    UNIQUE KEY uk_users_email (email),      -- No duplicate emails
    INDEX idx_users_active (is_active),      -- Speed up active user queries
    INDEX idx_users_created (created_at)     -- Speed up date-range queries
);
```

### Column Constraints

| Constraint | Purpose | Example |
|------------|---------|---------|
| `PRIMARY KEY` | Unique identifier, not null, indexed | `id BIGINT PRIMARY KEY` |
| `NOT NULL` | Value required | `email VARCHAR(255) NOT NULL` |
| `UNIQUE` | All values distinct | `email VARCHAR(255) UNIQUE` |
| `DEFAULT` | Auto-fill if omitted | `is_active BOOLEAN DEFAULT TRUE` |
| `CHECK` | Custom validation | `age INT CHECK (age >= 18)` |
| `AUTO_INCREMENT` / `SERIAL` | Auto-generate IDs | `id INT AUTO_INCREMENT` |
| `COMMENT` | Documentation | `price DECIMAL(10,2) COMMENT 'USD'` |

### Table-Level Constraints

```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    status ENUM('pending', 'paid', 'shipped', 'delivered', 'cancelled') DEFAULT 'pending',
    subtotal DECIMAL(10,2) NOT NULL,
    tax DECIMAL(10,2) NOT NULL DEFAULT 0,
    shipping DECIMAL(10,2) NOT NULL DEFAULT 0,
    total DECIMAL(10,2) NOT NULL,
    currency CHAR(3) NOT NULL DEFAULT 'USD',

    -- Foreign key: links to users table
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE RESTRICT
        ON UPDATE CASCADE,

    -- Check constraint: total = subtotal + tax + shipping
    CONSTRAINT chk_orders_total
        CHECK (total = subtotal + tax + shipping),

    -- Check: no negative amounts
    CONSTRAINT chk_orders_positive
        CHECK (subtotal >= 0 AND tax >= 0 AND shipping >= 0),

    INDEX idx_orders_user (user_id),
    INDEX idx_orders_status (status),
    INDEX idx_orders_created (created_at)
);
```

## Foreign Keys: Referential Integrity

```
USERS (parent)          ORDERS (child)
┌────┬────────┐         ┌────┬────────┬────────┐
│ id │ name   │         │ id │ user_id │ total  │
├────┼────────┤         ├────┼────────┼────────┤
│ 1  │ Alice  │  ←───   │ 101│ 1       │ 99.99  │
│ 2  │ Bob    │         │ 102│ 1       │ 149.50 │
│ 3  │ Carol  │         │ 103│ 2       │ 75.00  │
└────┴────────┘         └────┴────────┴────────┘
```

### ON DELETE / ON UPDATE Actions

| Action | Behavior | Use Case |
|--------|----------|----------|
| `RESTRICT` / `NO ACTION` | Block delete/update if children exist | **Default** - protects data integrity |
| `CASCADE` | Delete/update children automatically | `orders` → `order_items` (items die with order) |
| `SET NULL` | Set FK to NULL (column must be nullable) | `comments` → `users` (keep comment, anonymize author) |
| `SET DEFAULT` | Set FK to column default | Rarely used |

```sql
-- Order items cascade with orders (when order deleted, items deleted)
FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE

-- User profile set NULL if user deleted (preserve content)
FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL

-- Prevent deleting category if products exist
FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE RESTRICT
```

## Modifying Tables (ALTER TABLE)

```sql
-- Add column
ALTER TABLE users ADD COLUMN bio TEXT;

-- Add column with position (MySQL)
ALTER TABLE users ADD COLUMN middle_name VARCHAR(50) AFTER full_name;

-- Drop column
ALTER TABLE users DROP COLUMN middle_name;

-- Modify column (change type, constraints)
ALTER TABLE users MODIFY COLUMN email VARCHAR(320) NOT NULL;  -- RFC 5321 max

-- Rename column (MySQL 8.0+ / PostgreSQL)
ALTER TABLE users RENAME COLUMN phone TO phone_number;

-- Add index
ALTER TABLE users ADD INDEX idx_users_name (full_name);

-- Add unique constraint
ALTER TABLE users ADD CONSTRAINT uk_users_phone UNIQUE (phone_number);

-- Add foreign key
ALTER TABLE orders ADD CONSTRAINT fk_orders_user
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE RESTRICT;

-- Drop foreign key
ALTER TABLE orders DROP FOREIGN KEY fk_orders_user;

-- Rename table
RENAME TABLE users TO customers;
-- Or: ALTER TABLE users RENAME TO customers;
```

## Dropping Tables & Databases

```sql
-- Drop table (data lost!)
DROP TABLE users;

-- Safe drop (no error if missing)
DROP TABLE IF EXISTS users;

-- Drop with cascade (PostgreSQL: drop dependent objects)
DROP TABLE users CASCADE;

-- Drop database
DROP DATABASE ecommerce;
DROP DATABASE IF EXISTS ecommerce;
```

> **⚠️ Warning**: `DROP` is irreversible. Always backup first. Use `TRUNCATE` to empty a table but keep structure.

## Viewing Structure

```sql
-- MySQL
SHOW TABLES;
DESCRIBE users;           -- or DESC users;
SHOW CREATE TABLE users;  -- Full CREATE statement

-- PostgreSQL
\dt                       -- List tables
\d users                  -- Describe table
\d+ users                 -- Verbose (with sizes, comments)

-- Information Schema (standard, works everywhere)
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema = 'ecommerce' AND table_name = 'users';
```
