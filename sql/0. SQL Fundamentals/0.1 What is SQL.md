# What is SQL

**SQL (Structured Query Language)** is the standard language for managing and querying **relational databases**.

## What is a Relational Database?

A relational database organizes data into **tables** (like spreadsheets) where:
- **Rows** = individual records (one user, one order, one product)
- **Columns** = attributes (name, email, price, date)
- **Relationships** = tables connect via shared columns (keys)

```
┌─────────────────────────────────────────────────────────────┐
│                    USERS TABLE                               │
├──────┬──────────┬──────────────────────┬────────────────────┤
│ id   │ name     │ email                │ created_at         │
├──────┼──────────┼──────────────────────┼────────────────────┤
│ 1    │ Alice    │ alice@example.com    │ 2024-01-15 10:30:00│
│ 2    │ Bob      │ bob@example.com      │ 2024-01-16 14:22:00│
│ 3    │ Charlie  │ charlie@example.com  │ 2024-01-17 09:15:00│
└──────┴──────────┴──────────────────────┴────────────────────┘
```

## What Can SQL Do?

| Category | Commands | Purpose |
|----------|----------|---------|
| **Query** | `SELECT` | Read/retrieve data |
| **Manipulate (DML)** | `INSERT`, `UPDATE`, `DELETE` | Modify data |
| **Define (DDL)** | `CREATE`, `ALTER`, `DROP` | Structure tables |
| **Control (DCL)** | `GRANT`, `REVOKE` | Permissions |
| **Transaction (TCL)** | `COMMIT`, `ROLLBACK` | Data integrity |

## Basic Query Structure

```sql
-- Simplest query: get all columns, all rows
SELECT * FROM users;

-- Practical query: specific columns with filtering
SELECT name, email
FROM users
WHERE created_at >= '2024-01-01'
ORDER BY created_at DESC;
```

## SQL vs NoSQL

| SQL (Relational) | NoSQL (Non-Relational) |
|------------------|------------------------|
| Fixed schema | Flexible schema |
| ACID transactions | Often eventual consistency |
| Complex queries (JOINs) | Simple key-value access |
| Vertical scaling | Horizontal scaling |
| Examples: PostgreSQL, MySQL, SQL Server | Examples: MongoDB, Redis, Cassandra |

## Popular SQL Databases

| Database | Best For | Notes |
|----------|----------|-------|
| **PostgreSQL** | General purpose, advanced features | Most feature-complete open source |
| **MySQL/MariaDB** | Web apps, read-heavy workloads | Very popular, good performance |
| **SQLite** | Embedded, mobile, testing | File-based, zero config |
| **SQL Server** | Enterprise, .NET ecosystem | Microsoft, robust tooling |
| **Oracle** | Large enterprise | Expensive, powerful |

## Why Learn SQL?

1. **Universal** - Works across all relational databases (95% same syntax)
2. **In-demand** - Required for backend, data analysis, data science, DevOps
3. **Direct data access** - Skip ORM limitations, write optimized queries
4. **Foundation** - Understand what ORMs (Eloquent, Hibernate, Entity Framework) do under the hood
