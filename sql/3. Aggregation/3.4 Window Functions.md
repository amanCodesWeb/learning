# Window Functions — Analytics Without Grouping

Window functions compute aggregates/rankings **over a window of rows** while keeping each row in the result. Essential for analytics.

---

## Why Window Functions?

```sql
-- Without window functions: need subquery or JOIN
SELECT o.*, u.total_revenue
FROM orders o
JOIN (SELECT user_id, SUM(total) AS total_revenue FROM orders GROUP BY user_id) u
    ON o.user_id = u.user_id;

-- With window function: single pass, cleaner
SELECT
    o.*
    , SUM(total) OVER (PARTITION BY user_id) AS user_revenue
FROM orders o;
```

---

## Syntax

```sql
function_name([arguments]) OVER (
    [PARTITION BY column(s)]          -- Divide rows into groups
    [ORDER BY column(s) [ASC|DESC]]   -- Order within partition
    [FRAME_CLAUSE]                    -- Subset of partition (advanced)
)
```

---

## Function Categories

| Category | Functions |
|----------|-----------|
| **Aggregate** | `SUM`, `AVG`, `COUNT`, `MIN`, `MAX`, `STDDEV` |
| **Ranking** | `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `NTILE` |
| **Value** | `FIRST_VALUE`, `LAST_VALUE`, `LEAD`, `LAG`, `NTH_VALUE` |
| **Distribution** | `PERCENT_RANK`, `CUME_DIST` |

## PARTITION BY — Group Without Collapsing

```sql
-- Revenue per user on every order row
SELECT
    id, user_id, total, created_at
    , SUM(total) OVER (PARTITION BY user_id) AS user_revenue
    , COUNT(*) OVER (PARTITION BY user_id) AS user_orders
    , AVG(total) OVER (PARTITION BY user_id) AS user_avg
FROM orders;

-- Multiple partitions
SELECT
    o.*
    , SUM(total) OVER (PARTITION BY user_id) AS user_revenue
    , SUM(total) OVER (PARTITION BY DATE(created_at)) AS daily_revenue
FROM orders;
```

## ORDER BY in Window — Running Totals, Rankings

```sql
-- Running total (cumulative sum)
SELECT
    created_at, total
    , SUM(total) OVER (ORDER BY created_at) AS running_total
FROM orders WHERE user_id = 1;

-- Rank by order size (per user)
SELECT
    id, user_id, total
    , RANK() OVER (PARTITION BY user_id ORDER BY total DESC) AS size_rank
    , DENSE_RANK() OVER (PARTITION BY user_id ORDER BY total DESC) AS dense_rank
    , ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY total DESC) AS row_num
FROM orders;
```

### Ranking Functions Compared

| Function | Ties | Sequence |
|----------|------|----------|
| `ROW_NUMBER()` | Breaks ties arbitrarily | 1, 2, 3, 4... |
| `RANK()` | Same rank, skips next | 1, 2, 2, 4... |
| `DENSE_RANK()` | Same rank, no skip | 1, 2, 2, 3... |
| `NTILE(n)` | Buckets | 1,1,2,2,3,3... |

```sql
-- Example: values 100, 90, 90, 80
SELECT
    val
    , ROW_NUMBER() OVER (ORDER BY val DESC)   -- 1, 2, 3, 4
    , RANK() OVER (ORDER BY val DESC)         -- 1, 2, 2, 4
    , DENSE_RANK() OVER (ORDER BY val DESC)   -- 1, 2, 2, 3
    , NTILE(2) OVER (ORDER BY val DESC)       -- 1, 1, 2, 2
FROM (VALUES (100),(90),(90),(80)) t(val);
```

## LEAD / LAG — Access Neighboring Rows

```sql
-- Previous and next order per user
SELECT
    id, user_id, total, created_at
    , LAG(total) OVER (PARTITION BY user_id ORDER BY created_at) AS prev_order
    , LEAD(total) OVER (PARTITION BY user_id ORDER BY created_at) AS next_order
    , total - LAG(total) OVER (PARTITION BY user_id ORDER BY created_at) AS diff_from_prev
FROM orders;

-- Time since last order
SELECT
    id, user_id, created_at
    , LAG(created_at) OVER (PARTITION BY user_id ORDER BY created_at) AS prev_date
    , DATEDIFF(created_at, LAG(created_at) OVER (PARTITION BY user_id ORDER BY created_at)) AS days_since_last
FROM orders;
```

## FIRST_VALUE / LAST_VALUE — Boundary Values

```sql
-- First and last order per user
SELECT
    id, user_id, total, created_at
    , FIRST_VALUE(total) OVER (PARTITION BY user_id ORDER BY created_at) AS first_order
    , LAST_VALUE(total) OVER (
        PARTITION BY user_id ORDER BY created_at
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS last_order
FROM orders;

-- ⚠️ LAST_VALUE default frame is wrong! Must specify full frame.
-- Default frame: RANGE UNBOUNDED PRECEDING AND CURRENT ROW
-- So LAST_VALUE returns current row's value!
```

## NTILE — Percentiles / Buckets

```sql
-- Divide customers into 10 equal groups by revenue
SELECT
    user_id
    , SUM(total) AS revenue
    , NTILE(10) OVER (ORDER BY SUM(total) DESC) AS decile
FROM orders
GROUP BY user_id;

-- Quartiles (4 buckets)
SELECT
    user_id, revenue
    , NTILE(4) OVER (ORDER BY revenue DESC) AS quartile
FROM (SELECT user_id, SUM(total) AS revenue FROM orders GROUP BY user_id) t;

-- Percentile (100 buckets)
NTILE(100) OVER (ORDER BY revenue DESC) AS percentile
```

## Frame Clauses — Precise Window Control

```sql
-- Default frame (when ORDER BY present):
-- RANGE UNBOUNDED PRECEDING AND CURRENT ROW

-- Explicit frames (use ROWS for predictable behavior):
SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW  -- Running total
)

SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY created_at
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW          -- 3-row moving sum
)

SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING  -- Full partition sum
)
```

### Frame Types

| Frame | Use Case |
|-------|----------|
| `ROWS` | Physical row count (faster, predictable) |
| `RANGE` | Value-based (same ORDER BY value = same frame) |
| `GROUPS` | Group-based (PostgreSQL 11+) |

## Practical Patterns

### 1. Top-N Per Group
```sql
-- Top 3 orders per user
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY total DESC) AS rn
    FROM orders
)
SELECT * FROM ranked WHERE rn <= 3;
```

### 2. First/Last Per Group
```sql
-- First order per user
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at) AS rn
    FROM orders
)
SELECT * FROM ranked WHERE rn = 1;

-- Or with FIRST_VALUE (single pass)
SELECT DISTINCT
    user_id
    , FIRST_VALUE(id) OVER (PARTITION BY user_id ORDER BY created_at) AS first_order_id
    , FIRST_VALUE(total) OVER (PARTITION BY user_id ORDER BY created_at) AS first_total
FROM orders;
```

### 3. Gap Detection (Missing Sequence)
```sql
-- Find missing order numbers per user
SELECT
    user_id
    , id AS current_order
    , LAG(id) OVER (PARTITION BY user_id ORDER BY id) AS prev_order
    , id - LAG(id) OVER (PARTITION BY user_id ORDER BY id) - 1 AS gap_size
FROM orders
WHERE id - LAG(id) OVER (PARTITION BY user_id ORDER BY id) > 1;
```

### 4. Sessionization (Group Events by Time Gap)
```sql
-- New session if >30 min since last event
WITH lagged AS (
    SELECT
        user_id, event_time
        , LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time) AS prev_time
    FROM events
), sessions AS (
    SELECT
        user_id, event_time
        , SUM(CASE WHEN prev_time IS NULL OR event_time > prev_time + INTERVAL '30 minute' THEN 1 ELSE 0 END)
            OVER (PARTITION BY user_id ORDER BY event_time) AS session_id
    FROM lagged
)
SELECT user_id, session_id, MIN(event_time) AS start, MAX(event_time) AS end
FROM sessions GROUP BY user_id, session_id;
```

### 5. Running Difference / Growth
```sql
-- Month-over-month growth
SELECT
    month, revenue
    , LAG(revenue) OVER (ORDER BY month) AS prev_month
    , revenue - LAG(revenue) OVER (ORDER BY month) AS absolute_change
    , ROUND((revenue - LAG(revenue) OVER (ORDER BY month)) / LAG(revenue) OVER (ORDER BY month) * 100, 1) AS pct_change
FROM monthly_revenue;
```

## Window Functions vs GROUP BY

| Aspect | GROUP BY | Window Functions |
|--------|----------|------------------|
| **Rows returned** | One per group | Same as input |
| **Detail + aggregate** | Requires JOIN | Single query |
| **Performance** | Good for summaries | Can be slower on huge data |
| **Flexibility** | Limited | Very high |

---

## Performance Tips

```sql
-- 1. Index PARTITION BY + ORDER BY columns
CREATE INDEX idx_orders_user_date ON orders(user_id, created_at);

-- 2. Avoid window functions on huge unpartitioned sets
-- Bad: ROW_NUMBER() OVER (ORDER BY created_at) on 10M rows
-- Better: partition first, or use LIMIT with index

-- 3. Materialize if reused
WITH ranked AS (SELECT ..., ROW_NUMBER() OVER (...) AS rn FROM huge_table)
SELECT ... FROM ranked WHERE rn = 1;
```
