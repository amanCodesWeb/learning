# GROUP BY — Summarizing Data

`GROUP BY` collapses multiple rows into **one summary row per group**. It's the foundation of analytical queries.

---

## Basic Syntax

```sql
SELECT
    grouping_column(s)
    , aggregate_function(column) AS alias
FROM table_name
[WHERE condition]
GROUP BY grouping_column(s)
[HAVING condition]
[ORDER BY column];
```

## Basic GROUP BY

```sql
-- Count orders per user
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id;

-- Sum revenue per user
SELECT user_id, SUM(total) AS lifetime_value
FROM orders
GROUP BY user_id;

-- Multiple aggregates
SELECT
    user_id
    , COUNT(*) AS order_count
    , SUM(total) AS total_spent
    , AVG(total) AS avg_order
    , MIN(total) AS smallest_order
    , MAX(total) AS largest_order
FROM orders
GROUP BY user_id;
```

## GROUP BY Multiple Columns

```sql
-- Orders per user per status
SELECT
    user_id
    , status
    , COUNT(*) AS count
    , SUM(total) AS revenue
FROM orders
GROUP BY user_id, status
ORDER BY user_id, status;

-- Revenue by category and month
SELECT
    p.category
    , DATE_FORMAT(o.created_at, '%Y-%m') AS month
    , SUM(oi.total) AS revenue
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
JOIN products p ON oi.product_id = p.id
GROUP BY p.category, month
ORDER BY p.category, month;
```

## The "Only GROUP BY Columns or Aggregates" Rule

```sql
-- ✅ Valid: every non-aggregate column is in GROUP BY
SELECT user_id, status, COUNT(*)
FROM orders
GROUP BY user_id, status;

-- ❌ Invalid: 'email' not in GROUP BY and not aggregated
SELECT user_id, email, COUNT(*)
FROM orders
GROUP BY user_id;
-- ERROR: email is not functionally dependent on user_id

-- ✅ Fixed: add to GROUP BY or aggregate
SELECT user_id, email, COUNT(*)
FROM orders o
JOIN users u ON o.user_id = u.id
GROUP BY user_id, email;

-- MySQL ONLY_FULL_GROUP_BY mode (default in 5.7+): enforces this strictly
-- PostgreSQL: always enforces
-- SQLite: allows but picks arbitrary value (dangerous)
```

## GROUP BY with WHERE vs HAVING

| Clause | When | Filters |
|--------|------|---------|
| `WHERE` | **Before** grouping | Individual rows |
| `HAVING` | **After** grouping | Aggregated groups |

```sql
-- WHERE: filter rows before grouping
SELECT user_id, COUNT(*)
FROM orders
WHERE status = 'delivered'  -- Only delivered orders counted
GROUP BY user_id;

-- HAVING: filter groups after aggregation
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING COUNT(*) >= 5;  -- Only users with 5+ orders

-- Both together
SELECT user_id, COUNT(*) AS cnt, SUM(total) AS revenue
FROM orders
WHERE status IN ('paid', 'delivered')  -- Row filter
GROUP BY user_id
HAVING SUM(total) > 1000;              -- Group filter
```

## GROUP BY with Expressions

```sql
-- Group by computed value
SELECT
    CASE
        WHEN total < 100 THEN 'Small'
        WHEN total < 500 THEN 'Medium'
        ELSE 'Large'
    END AS order_size
    , COUNT(*) AS count
    , SUM(total) AS revenue
FROM orders
GROUP BY order_size;

-- Group by date parts
SELECT
    YEAR(created_at) AS year
    , MONTH(created_at) AS month
    , COUNT(*) AS orders
FROM orders
GROUP BY YEAR(created_at), MONTH(created_at);

-- Group by expression alias (MySQL, PostgreSQL)
SELECT
    DATE_FORMAT(created_at, '%Y-%m') AS yr_mo
    , COUNT(*)
FROM orders
GROUP BY yr_mo;
```

## Common Aggregate Functions

| Function | Purpose | Ignores NULL? |
|----------|---------|---------------|
| `COUNT(*)` | Row count | No (counts all rows) |
| `COUNT(col)` | Non-null count | Yes |
| `SUM(col)` | Total | Yes |
| `AVG(col)` | Average | Yes |
| `MIN(col)` | Minimum | Yes |
| `MAX(col)` | Maximum | Yes |
| `GROUP_CONCAT` / `STRING_AGG` | Concatenate values | Yes |

```sql
-- COUNT(*) vs COUNT(column)
SELECT
    COUNT(*) AS total_rows
    , COUNT(phone) AS phones_provided
    , COUNT(DISTINCT city) AS unique_cities
FROM users;

-- String aggregation
-- MySQL
SELECT category, GROUP_CONCAT(name ORDER BY name SEPARATOR ', ') AS products
FROM products GROUP BY category;

-- PostgreSQL
SELECT category, STRING_AGG(name, ', ' ORDER BY name) AS products
FROM products GROUP BY category;

-- Statistical (PostgreSQL)
SELECT
    STDDEV(price) AS stddev
    , VARIANCE(price) AS variance
    , PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY price) AS median
FROM products;
```

## GROUPING SETS / ROLLUP / CUBE (Advanced)

```sql
-- ROLLUP: subtotals + grand total
SELECT
    category
    , brand
    , SUM(price) AS revenue
FROM products
GROUP BY ROLLUP (category, brand);

-- Result:
-- category | brand | revenue
-- Laptops  | Apple | 2499
-- Laptops  | Lenovo| 1599
-- Laptops  | NULL  | 4098  ← subtotal
-- Phones   | Apple | 999
-- Phones   | Samsung| 899
-- Phones   | NULL  | 1898  ← subtotal
-- NULL     | NULL  | 5996  ← grand total

-- CUBE: all combinations
GROUP BY CUBE (category, brand);

-- GROUPING SETS: custom combinations
GROUP BY GROUPING SETS (
    (category, brand),
    (category),
    ()
);
```

> **Support**: PostgreSQL, SQL Server, Oracle. MySQL: use `WITH ROLLUP`.
