# HAVING — Filtering Groups

`HAVING` filters **after** aggregation. It's the `WHERE` clause for grouped data.

---

## WHERE vs HAVING

| Aspect | WHERE | HAVING |
|--------|-------|--------|
| **When** | Before GROUP BY | After GROUP BY |
| **Operates on** | Individual rows | Aggregated groups |
| **Can use** | Column values | Aggregate functions |
| **Alias support** | No | Yes (MySQL, PostgreSQL) |

```sql
-- WHERE: filters rows
SELECT user_id, COUNT(*)
FROM orders
WHERE status = 'delivered'  -- Row-level filter
GROUP BY user_id;

-- HAVING: filters groups
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING COUNT(*) > 5;  -- Group-level filter

-- Combined
SELECT user_id, COUNT(*) AS cnt, SUM(total) AS revenue
FROM orders
WHERE created_at >= '2024-01-01'  -- Row filter: 2024 orders only
GROUP BY user_id
HAVING SUM(total) > 1000;         -- Group filter: high-value customers
```

## HAVING with Aggregates

```sql
-- Count threshold
HAVING COUNT(*) >= 10

-- Sum threshold
HAVING SUM(total) > 10000

-- Average threshold
HAVING AVG(total) > 200

-- Multiple conditions
HAVING COUNT(*) >= 5 AND SUM(total) > 1000

-- Using column alias (MySQL, PostgreSQL)
SELECT user_id, COUNT(*) AS order_count
FROM orders
GROUP BY user_id
HAVING order_count > 5;
```

## HAVING with Complex Expressions

```sql
-- Percentage of total
SELECT category, SUM(total) AS cat_revenue
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
JOIN products p ON oi.product_id = p.id
GROUP BY category
HAVING SUM(total) / (SELECT SUM(total) FROM orders) > 0.1;  -- >10% of total

-- Conditional aggregation in HAVING
SELECT user_id
FROM orders
GROUP BY user_id
HAVING COUNT(CASE WHEN status = 'cancelled' THEN 1 END) = 0;  -- Never cancelled

-- Ratio
SELECT user_id
FROM orders
GROUP BY user_id
HAVING SUM(CASE WHEN status = 'delivered' THEN 1 ELSE 0 END) / COUNT(*) > 0.8;  -- 80% delivery rate
```

## Common Patterns

### 1. Find Duplicates
```sql
-- Emails used more than once
SELECT email, COUNT(*)
FROM users
GROUP BY email
HAVING COUNT(*) > 1;
```

### 2. "Having at Least N" Pattern
```sql
-- Users with at least 3 orders
SELECT user_id FROM orders GROUP BY user_id HAVING COUNT(*) >= 3;

-- Products ordered at least 10 times
SELECT product_id FROM order_items GROUP BY product_id HAVING SUM(quantity) >= 10;
```

### 3. "Having All/None" Pattern
```sql
-- Users who ordered ALL categories (relational division)
SELECT user_id
FROM orders o
JOIN order_items oi ON o.id = oi.order_id
JOIN products p ON oi.product_id = p.id
GROUP BY user_id
HAVING COUNT(DISTINCT p.category) = (SELECT COUNT(DISTINCT category) FROM products);

-- Users with NO cancelled orders
SELECT user_id
FROM orders
GROUP BY user_id
HAVING COUNT(CASE WHEN status = 'cancelled' THEN 1 END) = 0;
```

### 4. Time-Based HAVING
```sql
-- Customers active in last 6 months with >5 orders
SELECT user_id
FROM orders
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 6 MONTH)
GROUP BY user_id
HAVING COUNT(*) > 5;

-- Months with revenue > $10,000
SELECT DATE_FORMAT(created_at, '%Y-%m') AS month, SUM(total) AS revenue
FROM orders
GROUP BY month
HAVING SUM(total) > 10000;
```

## HAVING with Window Functions (Advanced)

```sql
-- Groups above average
SELECT user_id, SUM(total) AS revenue
FROM orders
GROUP BY user_id
HAVING SUM(total) > (SELECT AVG(user_revenue) FROM (
    SELECT SUM(total) AS user_revenue FROM orders GROUP BY user_id
) t);

-- Top 10% of customers by revenue (NTILE)
WITH ranked AS (
    SELECT user_id, SUM(total) AS revenue,
           NTILE(10) OVER (ORDER BY SUM(total) DESC) AS decile
    FROM orders GROUP BY user_id
)
SELECT user_id, revenue FROM ranked WHERE decile = 1;
```

## Performance: HAVING vs WHERE

```sql
-- ❌ Slow: HAVING does work WHERE could do
SELECT user_id, COUNT(*)
FROM orders
GROUP BY user_id
HAVING user_id IN (SELECT id FROM users WHERE country = 'USA');

-- ✅ Fast: WHERE reduces rows before grouping
SELECT user_id, COUNT(*)
FROM orders
WHERE user_id IN (SELECT id FROM users WHERE country = 'USA')
GROUP BY user_id;

-- ❌ Slow: HAVING on non-aggregate (move to WHERE)
SELECT user_id, COUNT(*)
FROM orders
GROUP BY user_id
HAVING status = 'delivered';  -- status not aggregated!

-- ✅ Fast: WHERE filters rows
SELECT user_id, COUNT(*)
FROM orders
WHERE status = 'delivered'
GROUP BY user_id;
```
