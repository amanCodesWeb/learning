# DISTINCT & Aliases

`DISTINCT` removes duplicate rows. Aliases (`AS`) give meaningful names to columns and tables.

---

## DISTINCT — Removing Duplicates

```sql
-- Single column: unique values
SELECT DISTINCT category FROM products;

-- Multiple columns: unique combinations
SELECT DISTINCT category, brand FROM products;

-- With WHERE
SELECT DISTINCT city FROM users WHERE country = 'USA';

-- With ORDER BY
SELECT DISTINCT category FROM products ORDER BY category;

-- With LIMIT
SELECT DISTINCT brand FROM products ORDER BY brand LIMIT 10;
```

### How DISTINCT Works

```sql
-- This data:
-- category | brand
-- Laptops  | Apple
-- Laptops  | Lenovo
-- Phones   | Apple
-- Laptops  | Apple   ← duplicate

SELECT DISTINCT category, brand FROM products;
-- Returns 3 rows (Laptops+Apple counted once)
```

> **Key Point**: `DISTINCT` applies to **all selected columns** as a unit. It doesn't make one column unique while keeping others.

### DISTINCT ON (PostgreSQL Only)

```sql
-- First row per category (by price DESC)
SELECT DISTINCT ON (category) category, name, price
FROM products
ORDER BY category, price DESC;

-- Equivalent standard SQL (window function):
SELECT category, name, price FROM (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC) AS rn
    FROM products
) t WHERE rn = 1;
```

### COUNT(DISTINCT ...)

```sql
-- Count unique categories
SELECT COUNT(DISTINCT category) FROM products;

-- Count unique customers who ordered
SELECT COUNT(DISTINCT user_id) FROM orders;

-- Multiple distinct counts
SELECT
    COUNT(DISTINCT category) AS categories
    , COUNT(DISTINCT brand) AS brands
    , COUNT(*) AS total_products
FROM products;
```

## Aliases — Naming Columns & Tables

### Column Aliases

```sql
-- AS keyword (recommended for clarity)
SELECT
    id AS user_id
    , email AS user_email
    , CONCAT(first_name, ' ', last_name) AS full_name
    , price * quantity AS line_total
FROM order_items;

-- Without AS (works but less clear)
SELECT id user_id, email user_email FROM users;

-- Alias required for computed columns
SELECT
    COUNT(*) AS order_count
    , SUM(total) AS revenue
FROM orders;
```

> **Best Practice**: Always use `AS` for column aliases. It's standard SQL and prevents ambiguity.

### Table Aliases

```sql
-- Short, meaningful aliases (1-3 letters related to table name)
SELECT u.id, u.email, o.total
FROM users AS u
JOIN orders AS o ON u.id = o.user_id;

-- Required when joining same table multiple times
SELECT
    u1.email AS user_email
    , u2.email AS referrer_email
FROM users AS u1
LEFT JOIN users AS u2 ON u1.referred_by = u2.id;

-- In subqueries
SELECT * FROM (
    SELECT user_id, SUM(total) AS lifetime_value
    FROM orders
    GROUP BY user_id
) AS lv
JOIN users u ON lv.user_id = u.id;
```

### Alias Naming Conventions

| Type | Convention | Examples |
|------|------------|----------|
| **Table** | 1-3 letters, lowercase | `u` (users), `o` (orders), `oi` (order_items), `p` (products) |
| **Column** | snake_case, descriptive | `user_id`, `order_count`, `lifetime_value`, `price_with_tax` |
| **Subquery** | descriptive suffix | `ranked`, `aggregated`, `filtered`, `latest` |

```sql
-- ✅ Good aliases
FROM users AS u
FROM order_items AS oi
FROM (SELECT ...) AS monthly_sales

-- ❌ Bad aliases
FROM users AS users_table      -- Redundant
FROM orders AS o1, orders AS o2 -- Unclear relationship
FROM (SELECT ...) AS t         -- Meaningless
```

## Aliases in Different Clauses

```sql
-- WHERE: CANNOT use column alias (execution order!)
SELECT name, price * 1.1 AS price_with_tax
FROM products
WHERE price_with_tax > 100;  -- ❌ ERROR: alias not available yet

-- Fix: repeat expression or use subquery
SELECT name, price * 1.1 AS price_with_tax
FROM products
WHERE price * 1.1 > 100;  -- ✅

-- Or subquery/CTE
SELECT * FROM (
    SELECT name, price * 1.1 AS price_with_tax FROM products
) AS t WHERE price_with_tax > 100;  -- ✅

-- GROUP BY: CAN use alias (MySQL, PostgreSQL) or position
SELECT category, COUNT(*) AS cnt
FROM products
GROUP BY category;           -- ✅ Standard
GROUP BY 1;                  -- ✅ Position (avoid)
GROUP BY category, cnt;      -- ❌ cnt not available in GROUP BY

-- HAVING: CAN use alias
SELECT category, COUNT(*) AS cnt
FROM products
GROUP BY category
HAVING cnt > 5;              -- ✅ Works in MySQL, PostgreSQL

-- ORDER BY: CAN use alias (all databases)
SELECT name, price * 1.1 AS price_with_tax
FROM products
ORDER BY price_with_tax DESC;  -- ✅ Works everywhere
```

## Practical Examples

### 1. Clean Report Queries
```sql
SELECT
    u.id AS user_id
    , u.email
    , u.full_name
    , COUNT(o.id) AS total_orders
    , COALESCE(SUM(o.total), 0) AS lifetime_value
    , MAX(o.created_at) AS last_order_date
FROM users AS u
LEFT JOIN orders AS o ON u.id = o.user_id
GROUP BY u.id, u.email, u.full_name
ORDER BY lifetime_value DESC;
```

### 2. Self-Join with Clear Aliases
```sql
-- Employee → Manager hierarchy
SELECT
    e.id AS employee_id
    , e.name AS employee_name
    , m.id AS manager_id
    , m.name AS manager_name
FROM employees AS e
LEFT JOIN employees AS m ON e.manager_id = m.id;
```

### 3. Subquery with Alias
```sql
-- Users with above-average order value
SELECT u.*, avg_order.avg_value
FROM users AS u
JOIN (
    SELECT user_id, AVG(total) AS avg_value
    FROM orders
    GROUP BY user_id
) AS avg_order ON u.id = avg_order.user_id
WHERE avg_order.avg_value > (
    SELECT AVG(total) FROM orders
);
```

## Common Mistakes

| Mistake | Problem | Fix |
|---------|---------|-----|
| Using alias in WHERE | Execution order: WHERE before SELECT | Repeat expression or use subquery |
| No alias on computed column | Result column has ugly name | Always `AS meaningful_name` |
| Generic aliases (`t`, `tmp`, `x`) | Hard to debug, unclear in errors | Descriptive: `monthly_sales`, `ranked_users` |
| Same alias for different tables | Ambiguity in JOINs | Unique per table: `u`, `o`, `p` |
| `DISTINCT` on many columns | Expensive, often unintended | Be specific; use `GROUP BY` if aggregating |
