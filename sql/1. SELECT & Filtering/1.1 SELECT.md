# SELECT — Retrieving Data

The `SELECT` statement is the most used SQL command. It reads data from tables without modifying anything.

---

## Basic Syntax

```sql
SELECT column1, column2, ...
FROM table_name
[WHERE condition]
[GROUP BY column(s)]
[HAVING condition]
[ORDER BY column(s) [ASC|DESC]]
[LIMIT count [OFFSET skip]];
```

> **Execution Order** (not written order):
> 1. `FROM` / `JOIN` — determine data source
> 2. `WHERE` — filter rows
> 3. `GROUP BY` — aggregate rows
> 4. `HAVING` — filter groups
> 5. `SELECT` — choose/transform columns
> 6. `ORDER BY` — sort results
> 7. `LIMIT` / `OFFSET` — paginate

---

## Selecting Columns

```sql
-- All columns (⚠️ avoid in production)
SELECT * FROM users;

-- Specific columns (✅ explicit, faster, clearer)
SELECT id, email, full_name, created_at FROM users;

-- With table alias (essential for JOINs)
SELECT u.id, u.email, u.full_name
FROM users AS u;
```

### Column Aliases

```sql
-- AS keyword (optional but recommended for clarity)
SELECT
    id AS user_id
    , email AS user_email
    , full_name AS name
    , created_at AS joined_at
FROM users;

-- Expression aliases
SELECT
    CONCAT(first_name, ' ', last_name) AS full_name
    , price * quantity AS line_total
    , NOW() AS query_time
FROM orders;
```

### Computed Columns

```sql
-- Arithmetic
SELECT price, quantity, price * quantity AS total
FROM order_items;

-- String functions
SELECT
    UPPER(email) AS email_upper
    , LOWER(full_name) AS name_lower
    , CONCAT('User: ', full_name) AS label
    , SUBSTRING(email, 1, INSTR(email, '@') - 1) AS username
FROM users;

-- Date functions
SELECT
    created_at
    , DATE(created_at) AS created_date
    , YEAR(created_at) AS created_year
    , MONTHNAME(created_at) AS created_month
    , DATEDIFF(NOW(), created_at) AS days_since_join
FROM users;

-- Conditional expressions
SELECT
    id
    , name
    , CASE
        WHEN price < 50 THEN 'Budget'
        WHEN price < 200 THEN 'Mid-range'
        ELSE 'Premium'
      END AS price_tier
FROM products;
```

## DISTINCT — Remove Duplicates

```sql
-- Unique values in one column
SELECT DISTINCT category_id FROM products;

-- Unique combinations across columns
SELECT DISTINCT category_id, brand_id FROM products;

-- Count distinct
SELECT COUNT(DISTINCT category_id) AS category_count FROM products;

-- ⚠️ DISTINCT applies to ALL selected columns
-- This returns unique (category, brand) pairs, not unique categories
SELECT DISTINCT category_id, brand_id FROM products;
```

## LIMIT & OFFSET — Pagination

```sql
-- First 10 rows
SELECT * FROM users LIMIT 10;

-- Rows 11-20 (page 2, 10 per page)
SELECT * FROM users LIMIT 10 OFFSET 10;

-- Shorthand (MySQL/PostgreSQL/SQLite)
SELECT * FROM users LIMIT 10 OFFSET 10;
-- Or: LIMIT 10, 10  (MySQL only: LIMIT offset, count)

-- With ORDER BY (essential for consistent pagination)
SELECT * FROM users
ORDER BY created_at DESC
LIMIT 20 OFFSET 40;  -- Page 3, 20 per page
```

> **Performance Note**: Large OFFSETs are slow (database scans skipped rows). For deep pagination, use **keyset pagination**:
```sql
-- Keyset pagination (seek method) - much faster for large offsets
SELECT * FROM users
WHERE created_at < '2024-01-15 10:30:00'  -- Last seen timestamp
ORDER BY created_at DESC
LIMIT 20;
```

## Practice Exercises

### Exercise 1: Basic SELECT
Using the sample data, write queries for:

1. **All active users' emails and names**
   ```sql
   SELECT email, full_name FROM users WHERE is_active = TRUE;
   ```

2. **All products with price > $1000, show name, brand, price**
   ```sql
   SELECT name, brand, price FROM products WHERE price > 1000;
   ```

3. **Orders with total > $1000, show id, user_id, total, status**
   ```sql
   SELECT id, user_id, total, status FROM orders WHERE total > 1000;
   ```

### Exercise 2: Computed Columns
1. **Products with profit margin** (price - cost) / price * 100 as percentage
   ```sql
   SELECT name, price, cost, ROUND((price - cost) / price * 100, 1) AS margin_pct
   FROM products;
   ```

2. **Orders with item count** (join order_items, count per order)
   ```sql
   SELECT o.id, o.user_id, COUNT(oi.id) AS item_count, o.total
   FROM orders o
   LEFT JOIN order_items oi ON o.id = oi.order_id
   GROUP BY o.id, o.user_id, o.total;
   ```

### Exercise 3: DISTINCT & LIMIT
1. **Unique categories from products**
   ```sql
   SELECT DISTINCT category FROM products ORDER BY category;
   ```

2. **Top 3 most expensive products**
   ```sql
   SELECT name, brand, price FROM products ORDER BY price DESC LIMIT 3;
   ```

3. **Unique cities from active users**
   ```sql
   SELECT DISTINCT city FROM users WHERE is_active = TRUE AND city IS NOT NULL;
   ```

## Common Mistakes

| Mistake | Problem | Fix |
|---------|---------|-----|
| `SELECT *` in production | Breaks when schema changes, slower | List columns explicitly |
| No `ORDER BY` with `LIMIT` | Random/unpredictable results | Always `ORDER BY` with `LIMIT` |
| `DISTINCT` on many columns | Expensive, often unintended | Be specific about what needs uniqueness |
| Large `OFFSET` | Slow (scans skipped rows) | Use keyset pagination |
| No alias on computed columns | Results have ugly names like `price * quantity` | Always `AS meaningful_name` |
