# WHERE — Filtering Rows

The `WHERE` clause filters rows **before** any grouping or aggregation. It's the primary way to narrow down your data.

---

## Basic Syntax

```sql
SELECT column1, column2, ...
FROM table_name
WHERE condition
[AND | OR condition ...];
```

---

## Comparison Operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `=` | Equal | `status = 'active'` |
| `!=` / `<>` | Not equal | `status != 'cancelled'` |
| `>` | Greater than | `price > 100` |
| `>=` | Greater or equal | `age >= 18` |
| `<` | Less than | `stock < 10` |
| `<=` | Less or equal | `created_at <= '2024-12-31'` |

```sql
-- Exact match
SELECT * FROM users WHERE email = 'alice@example.com';

-- Numeric range
SELECT * FROM products WHERE price >= 500 AND price <= 1500;

-- Date range
SELECT * FROM orders
WHERE created_at >= '2024-01-01'
    AND created_at < '2025-01-01';  -- Best practice: half-open interval
```

---

## Logical Operators

### AND / OR / NOT

```sql
-- AND: both conditions must be true
SELECT * FROM users
WHERE is_active = TRUE
    AND country = 'USA';

-- OR: at least one condition true
SELECT * FROM products
WHERE category = 'Laptops'
    OR category = 'Phones';

-- NOT: negate condition
SELECT * FROM users
WHERE NOT is_active;           -- Same as: WHERE is_active = FALSE
WHERE NOT (country = 'USA');   -- Same as: WHERE country != 'USA'

-- Combine with parentheses (critical for correct precedence)
SELECT * FROM orders
WHERE (status = 'paid' OR status = 'shipped')
    AND total > 500
    AND created_at >= '2024-01-01';
```

> **Precedence**: `NOT` > `AND` > `OR`. Always use parentheses when mixing `AND`/`OR`.

## IN / NOT IN — Multiple Values

```sql
-- Clean alternative to multiple OR
SELECT * FROM products
WHERE category IN ('Laptops', 'Phones', 'Tablets');

-- Subquery with IN
SELECT * FROM users
WHERE id IN (SELECT user_id FROM orders WHERE total > 1000);

-- NOT IN (⚠️ careful with NULLs in subquery!)
SELECT * FROM products
WHERE category NOT IN ('Accessories', 'Cases');

-- Values from another table
SELECT * FROM users
WHERE id IN (SELECT DISTINCT user_id FROM orders);
```

> **⚠️ NOT IN + NULL trap**: If subquery returns ANY NULL, `NOT IN` returns zero rows!
> ```sql
> -- Dangerous if any user_id is NULL
> WHERE id NOT IN (SELECT user_id FROM orders)
>
> -- Safe alternatives:
> WHERE NOT EXISTS (SELECT 1 FROM orders WHERE orders.user_id = users.id)
> WHERE id NOT IN (SELECT user_id FROM orders WHERE user_id IS NOT NULL)
> ```

## BETWEEN — Inclusive Range

```sql
-- Numbers
SELECT * FROM products WHERE price BETWEEN 100 AND 500;

-- Dates (inclusive both ends)
SELECT * FROM orders
WHERE created_at BETWEEN '2024-01-01' AND '2024-01-31 23:59:59';

-- Strings (alphabetical range)
SELECT * FROM users
WHERE last_name BETWEEN 'A' AND 'M';

-- NOT BETWEEN
SELECT * FROM products WHERE price NOT BETWEEN 100 AND 500;
```

> **Date Best Practice**: Use half-open intervals instead of BETWEEN for dates:
> ```sql
> -- ✅ Includes all of Jan 31, no timezone issues
> WHERE created_at >= '2024-01-01' AND created_at < '2024-02-01'
>
> -- ❌ Risky: depends on time precision, timezone
> WHERE created_at BETWEEN '2024-01-01' AND '2024-01-31'
> ```

## LIKE — Pattern Matching

| Wildcard | Matches |
|----------|---------|
| `%` | Zero or more characters |
| `_` | Exactly one character |
| `[abc]` | Any single character in set (SQL Server) |
| `[a-z]` | Range (SQL Server) |

```sql
-- Starts with
WHERE email LIKE 'admin%';

-- Ends with
WHERE email LIKE '%@company.com';

-- Contains anywhere
WHERE description LIKE '%wireless%';

-- Exact pattern: 3 letters, dash, 4 digits
WHERE sku LIKE '___-%_%';  -- or 'ABC-1234' pattern

-- Escape wildcard characters
WHERE code LIKE '100\%' ESCAPE '\';  -- Literal '%'
WHERE path LIKE '%/_/%' ESCAPE '/';  -- Literal '_'

-- Case sensitivity:
-- MySQL: default case-insensitive (depends on collation)
-- PostgreSQL: case-sensitive (use ILIKE for insensitive)
WHERE email ILIKE '%@GMAIL.COM';  -- PostgreSQL only
```

## IS NULL / IS NOT NULL

```sql
-- Find missing data
SELECT * FROM users WHERE phone IS NULL;

-- Find complete data
SELECT * FROM users WHERE phone IS NOT NULL;

-- In computed columns
SELECT
    id,
    COALESCE(phone, 'Not provided') AS phone_display
FROM users;

-- NULL-safe comparison (MySQL/PostgreSQL)
WHERE phone <=> '555-1234';   -- TRUE if both NULL or both '555-1234'
```

## Regular Expressions

### MySQL: `REGEXP` / `RLIKE`
```sql
-- Email pattern
WHERE email REGEXP '^[^@]+@[^@]+\.[^@]+$';

-- Phone: XXX-XXX-XXXX
WHERE phone REGEXP '^[0-9]{3}-[0-9]{3}-[0-9]{4}$';

-- Starts with vowel
WHERE name REGEXP '^[AEIOUaeiou]';

-- Case insensitive (default in MySQL)
WHERE name REGEXP '^john';  -- matches 'John', 'JOHN', 'john'

-- Case sensitive
WHERE name REGEXP BINARY '^John';
```

### PostgreSQL: `~` / `~*` / `!~` / `!~*`
```sql
-- Case sensitive
WHERE email ~ '^[^@]+@[^@]+\.[^@]+$';

-- Case insensitive (~*)
WHERE email ~* '^[^@]+@[^@]+\.[^@]+$';

-- Negative match
WHERE email !~ 'test';  -- doesn't contain 'test'
```

## Practical Filtering Patterns

### 1. Search with Multiple Optional Filters
```sql
-- Application-level: build WHERE dynamically
-- Or use this pattern (works but can be slow):
SELECT * FROM products
WHERE (:category IS NULL OR category = :category)
    AND (:brand IS NULL OR brand = :brand)
    AND (:min_price IS NULL OR price >= :min_price)
    AND (:max_price IS NULL OR price <= :max_price)
    AND (:search IS NULL OR name LIKE CONCAT('%', :search, '%'));
```

### 2. Date Ranges: Relative Time
```sql
-- Last 30 days (MySQL)
WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY);

-- Last 30 days (PostgreSQL)
WHERE created_at >= NOW() - INTERVAL '30 days';

-- This month
WHERE created_at >= DATE_TRUNC('month', CURRENT_DATE);

-- Previous month
WHERE created_at >= DATE_TRUNC('month', CURRENT_DATE) - INTERVAL '1 month'
    AND created_at < DATE_TRUNC('month', CURRENT_DATE);
```

### 3. Soft Delete Pattern
```sql
-- Always filter out deleted
WHERE deleted_at IS NULL;

-- Or with is_deleted flag
WHERE is_deleted = FALSE;
```

### 4. Status Filtering
```sql
-- Active orders (not cancelled, not pending)
WHERE status IN ('paid', 'shipped', 'delivered')

-- Open orders (can still be modified)
WHERE status IN ('pending', 'paid')

-- Completed orders
WHERE status IN ('delivered', 'cancelled')
```

## Performance Tips

| Tip | Why |
|-----|-----|
| Put most selective filter first | Reduces rows early |
| Avoid functions on columns | `WHERE YEAR(date) = 2024` can't use index on `date` |
| Use `EXPLAIN` to verify index usage | See if indexes are being used |
| `WHERE column = value` > `WHERE function(column) = value` | Sargable (Search ARGument ABLE) |
| `IN (subquery)` can be slow | Consider `EXISTS` or `JOIN` |

```sql
-- ❌ Not sargable - function on column prevents index use
WHERE YEAR(created_at) = 2024

-- ✅ Sargable - range on raw column uses index
WHERE created_at >= '2024-01-01' AND created_at < '2025-01-01'

-- ❌ Not sargable
WHERE UPPER(email) = 'ALICE@EXAMPLE.COM'

-- ✅ Sargable (if collation is case-insensitive)
WHERE email = 'alice@example.com'
```
