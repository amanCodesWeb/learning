# Subqueries — Queries Within Queries

A subquery (inner query) is a `SELECT` nested inside another statement. They enable complex logic in a single statement.

---

## Subquery Types by Location

| Location | Name | Returns |
|----------|------|---------|
| `WHERE` / `HAVING` | Nested subquery | Single value or list |
| `FROM` | Derived table / Inline view | Table (multiple rows/cols) |
| `SELECT` list | Scalar subquery | Single value |
| `WITH` (CTE) | Common Table Expression | Named temporary result |

---

## 1. WHERE Subqueries

### Scalar Subquery (Returns 1 Value)

```sql
-- Users with above-average order value
SELECT * FROM users
WHERE id IN (
    SELECT user_id FROM orders
    GROUP BY user_id
    HAVING AVG(total) > (SELECT AVG(total) FROM orders)
);

-- Products priced above category average
SELECT * FROM products p1
WHERE price > (
    SELECT AVG(price) FROM products p2 WHERE p2.category = p1.category
);
```

### Row Subquery (Returns 1 Row, Multiple Columns)

```sql
-- Find order matching exact (user, total, date)
SELECT * FROM orders
WHERE (user_id, total, created_at) = (
    SELECT user_id, total, created_at FROM orders WHERE id = 101
);
```

### List Subquery (IN / NOT IN)

```sql
-- Users who placed orders
SELECT * FROM users WHERE id IN (SELECT user_id FROM orders);

-- Users who NEVER ordered (⚠️ NULL trap with NOT IN)
SELECT * FROM users
WHERE id NOT IN (SELECT user_id FROM orders WHERE user_id IS NOT NULL);

-- Better: NOT EXISTS
SELECT * FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```

### Correlated Subquery (References Outer Query)

```sql
-- Each user's latest order date
SELECT u.*, (
    SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.id
) AS last_order_date
FROM users u;

-- Products with their order count
SELECT p.*, (
    SELECT COUNT(*) FROM order_items oi WHERE oi.product_id = p.id
) AS times_ordered
FROM products p;
```

> **Correlated subquery executes once per outer row** — can be slow on large tables. Often better as JOIN.

## 2. FROM Subqueries (Derived Tables)

```sql
-- Aggregate first, then join
SELECT d.user_id, d.order_count, u.email
FROM (
    SELECT user_id, COUNT(*) AS order_count
    FROM orders
    GROUP BY user_id
) AS d
JOIN users u ON d.user_id = u.id
WHERE d.order_count > 5;

-- Complex transformation
SELECT category, avg_price, product_count
FROM (
    SELECT
        category
        , AVG(price) AS avg_price
        , COUNT(*) AS product_count
    FROM products
    GROUP BY category
) AS cat_stats
WHERE avg_price > 500;
```

### Lateral Join (PostgreSQL/MySQL 8.0+) — Correlated FROM

```sql
-- Top 3 products per category (correlated derived table)
SELECT c.name AS category, p.name, p.price
FROM categories c
CROSS JOIN LATERAL (
    SELECT name, price FROM products p
    WHERE p.category_id = c.id
    ORDER BY price DESC LIMIT 3
) p;

-- MySQL 8.0: LATERAL keyword optional
CROSS JOIN (SELECT ... LIMIT 3) p;
```

## 3. SELECT List Subqueries (Scalar)

```sql
-- Add computed columns per row
SELECT
    u.id, u.full_name
    , (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS order_count
    , (SELECT SUM(total) FROM orders o WHERE o.user_id = u.id) AS total_spent
    , (SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.id) AS last_order
FROM users u;

-- ⚠️ Must return exactly 1 row, 1 column (or error)
```

## 4. CTEs (Common Table Expressions) — WITH Clause

```sql
-- Single CTE
WITH user_stats AS (
    SELECT
        user_id
        , COUNT(*) AS order_count
        , SUM(total) AS total_spent
        , AVG(total) AS avg_order
    FROM orders
    GROUP BY user_id
)
SELECT u.*, s.order_count, s.total_spent
FROM users u
JOIN user_stats s ON u.id = s.user_id
WHERE s.total_spent > 1000;

-- Multiple CTEs (chain them)
WITH
    recent_orders AS (
        SELECT * FROM orders WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
    ),
    user_recent AS (
        SELECT user_id, COUNT(*) AS recent_count, SUM(total) AS recent_spent
        FROM recent_orders GROUP BY user_id
    ),
    top_users AS (
        SELECT user_id FROM user_recent ORDER BY recent_spent DESC LIMIT 10
    )
SELECT u.*, r.recent_count, r.recent_spent
FROM users u
JOIN user_recent r ON u.id = r.user_id
JOIN top_users t ON r.user_id = t.user_id;
```

### Recursive CTEs (Hierarchical Data)

```sql
-- Employee hierarchy: employee → manager → director...
WITH RECURSIVE hierarchy AS (
    -- Anchor: top level (no manager)
    SELECT id, name, manager_id, 1 AS level, name::text AS path
    FROM employees WHERE manager_id IS NULL

    UNION ALL

    -- Recursive: join children
    SELECT e.id, e.name, e.manager_id, h.level + 1, h.path || ' > ' || e.name
    FROM employees e
    JOIN hierarchy h ON e.manager_id = h.id
)
SELECT * FROM hierarchy ORDER BY path;

-- Generate series (numbers, dates)
WITH RECURSIVE nums(n) AS (
    SELECT 1 UNION ALL SELECT n+1 FROM nums WHERE n < 10
)
SELECT * FROM nums;  -- 1 to 10
```

## EXISTS / NOT EXISTS — Existence Checks

```sql
-- EXISTS: true if subquery returns ANY row
-- Users with at least one delivered order
SELECT * FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.user_id = u.id AND o.status = 'delivered'
);

-- NOT EXISTS: true if subquery returns ZERO rows
-- Users with NO orders
SELECT * FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
);

-- Products never ordered
SELECT * FROM products p
WHERE NOT EXISTS (
    SELECT 1 FROM order_items oi WHERE oi.product_id = p.id
);
```

### EXISTS vs IN

| Aspect | IN | EXISTS |
|--------|-----|--------|
| **NULL handling** | Tricky (NOT IN fails with NULLs) | Clean (TRUE/FALSE only) |
| **Performance** | Optimizes to semi-join | Optimizes to semi-join |
| **Readability** | Simple for lists | Clear for "existence" |
| **Correlation** | Limited | Natural for correlated |

> **Rule**: Prefer `EXISTS`/`NOT EXISTS` for correlated subqueries. Use `IN` for simple lists.

## ANY / ALL / SOME — Compare to Subquery List

```sql
-- ANY: true if ANY comparison is true (same as SOME)
-- Products priced higher than ANY laptop
SELECT * FROM products
WHERE price > ANY (SELECT price FROM products WHERE category = 'Laptops');

-- Equivalent: price > MIN(laptop prices)

-- ALL: true if ALL comparisons are true
-- Products priced higher than ALL laptops
SELECT * FROM products
WHERE price > ALL (SELECT price FROM products WHERE category = 'Laptops');

-- Equivalent: price > MAX(laptop prices)

-- Use case: find outliers
SELECT * FROM orders
WHERE total > ALL (SELECT total * 2 FROM orders WHERE user_id = orders.user_id);
```

## Subquery Performance & Optimization

### 1. Convert to JOIN When Possible

```sql
-- Correlated subquery (slow)
SELECT u.*, (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS cnt
FROM users u;

-- JOIN (fast)
SELECT u.*, COUNT(o.id) AS cnt
FROM users u LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id;
```

### 2. Push Predicates Down

```sql
-- ❌ Subquery scans all orders
SELECT * FROM users u
WHERE u.id IN (SELECT user_id FROM orders WHERE total > 1000);

-- ✅ Predicate pushed (if optimizer doesn't do it)
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.total > 1000);
```

### 3. Materialize with CTE

```sql
-- Reuse expensive subquery
WITH expensive AS (
    SELECT user_id, SUM(total) AS revenue
    FROM orders GROUP BY user_id
)
SELECT * FROM users u
JOIN expensive e ON u.id = e.user_id
WHERE e.revenue > 1000;
```

### 4. LIMIT in Subquery

```sql
-- ❌ Some DBs don't allow LIMIT in IN subquery
WHERE id IN (SELECT user_id FROM orders ORDER BY total DESC LIMIT 10)

-- ✅ Use JOIN or EXISTS
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.user_id = u.id
    ORDER BY o.total DESC LIMIT 1
)
```
