# EXISTS & Correlated Subqueries

`EXISTS` checks if a subquery returns **any rows**. Returns boolean TRUE/FALSE — never NULL. Ideal for "existence" logic.

---

## EXISTS Syntax

```sql
SELECT columns
FROM outer_table
WHERE EXISTS (SELECT 1 FROM inner_table WHERE correlation_condition);

-- SELECT 1 is convention (any constant works: SELECT *, SELECT NULL, SELECT 42)
-- Database stops at FIRST matching row (short-circuits)
```

---

## EXISTS vs IN — The NULL Problem

```sql
-- IN with NOT IN: DANGEROUS if subquery has NULLs
SELECT * FROM users WHERE id NOT IN (SELECT user_id FROM orders);
-- If ANY user_id is NULL → returns ZERO rows (UNKNOWN = not TRUE)

-- EXISTS: SAFE, always works
SELECT * FROM users u WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
-- Returns users with no orders, regardless of NULLs
```

### Why NOT IN Fails with NULLs

```sql
-- Logic: 5 NOT IN (1, 2, NULL)
-- = NOT (5 = 1 OR 5 = 2 OR 5 = NULL)
-- = NOT (FALSE OR FALSE OR UNKNOWN)
-- = NOT (UNKNOWN) = UNKNOWN → filtered out!

-- EXISTS logic: TRUE/FALSE only, never UNKNOWN
```

> **Rule**: Never use `NOT IN` with a subquery. Use `NOT EXISTS` instead.

## Correlated Subqueries — Row-by-Row Execution

A correlated subquery references columns from the **outer query**. It executes **once per outer row**.

```sql
-- For each user, find their latest order
SELECT u.*, (
    SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.id
) AS last_order
FROM users u;

-- Equivalent with EXISTS (find users with recent orders)
SELECT u.* FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o
    WHERE o.user_id = u.id
      AND o.created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
);
```

### Correlation in WHERE vs SELECT

| Location | Use Case | Returns |
|----------|----------|---------|
| `WHERE EXISTS` | Filter rows | Boolean (row included or not) |
| `SELECT (subquery)` | Add computed column | Single value per row |

## EXISTS Patterns

### 1. "Has At Least One"
```sql
-- Users with any order
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id)

-- Users with delivered order
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id AND o.status = 'delivered')
```

### 2. "Has None" (Anti-Join)
```sql
-- Users with NO orders
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id)

-- Products NEVER ordered
WHERE NOT EXISTS (SELECT 1 FROM order_items oi WHERE oi.product_id = p.id)
```

### 3. "Has All" (Relational Division)
```sql
-- Users who ordered from EVERY category
SELECT u.* FROM users u
WHERE NOT EXISTS (
    SELECT c.id FROM categories c
    WHERE NOT EXISTS (
        SELECT 1 FROM orders o
        JOIN order_items oi ON o.id = oi.order_id
        JOIN products p ON oi.product_id = p.id
        WHERE o.user_id = u.id AND p.category_id = c.id
    )
);

-- Logic: No category exists that the user hasn't ordered from
```

### 4. "Has Any From Set"
```sql
-- Users who ordered ANY premium product
WHERE EXISTS (
    SELECT 1 FROM orders o
    JOIN order_items oi ON o.id = oi.order_id
    JOIN products p ON oi.product_id = p.id
    WHERE o.user_id = u.id AND p.price > 1000
)
```

### 5. Correlated UPDATE/DELETE

```sql
-- Update user's last_order_date
UPDATE users u
SET last_order_date = (
    SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.id
);

-- Delete users with no orders
DELETE FROM users
WHERE NOT EXISTS (SELECT 1 FROM orders WHERE user_id = users.id);

-- Delete orders older than 1 year for inactive users
DELETE FROM orders
WHERE user_id IN (SELECT id FROM users WHERE is_active = FALSE)
    AND created_at < DATE_SUB(NOW(), INTERVAL 1 YEAR);
```

## Correlated Subquery Performance

### Problem: Row-by-Row Execution

```sql
-- 10,000 users → subquery runs 10,000 times
SELECT u.*, (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS cnt
FROM users u;
```

### Solutions

#### 1. Convert to JOIN (Best)
```sql
SELECT u.*, COUNT(o.id) AS cnt
FROM users u LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.id;
```

#### 2. Use CTE to Pre-Aggregate
```sql
WITH order_counts AS (
    SELECT user_id, COUNT(*) AS cnt FROM orders GROUP BY user_id
)
SELECT u.*, COALESCE(oc.cnt, 0) AS cnt
FROM users u LEFT JOIN order_counts oc ON u.id = oc.user_id;
```

#### 3. LATERAL Join (PostgreSQL/MySQL 8.0+)
```sql
-- Correlated derived table (can return multiple rows)
SELECT u.*, o.cnt, o.last_order
FROM users u
LEFT JOIN LATERAL (
    SELECT COUNT(*) AS cnt, MAX(created_at) AS last_order
    FROM orders o WHERE o.user_id = u.id
) o ON TRUE;
```

#### 4. Window Functions (MySQL 8.0+, PostgreSQL)
```sql
-- Single pass
SELECT DISTINCT
    u.id, u.email
    , COUNT(o.id) OVER (PARTITION BY u.id) AS order_count
    , MAX(o.created_at) OVER (PARTITION BY u.id) AS last_order
FROM users u LEFT JOIN orders o ON u.id = o.user_id;
```

## EXISTS vs JOIN Performance

```sql
-- Often equivalent (optimizer transforms)
-- EXISTS (semi-join)
SELECT * FROM users u WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- JOIN (inner join)
SELECT DISTINCT u.* FROM users u JOIN orders o ON u.id = o.user_id;

-- LEFT JOIN + WHERE NULL (anti-join)
SELECT u.* FROM users u LEFT JOIN orders o ON u.id = o.user_id WHERE o.id IS NULL;

-- NOT EXISTS (anti-join)
SELECT u.* FROM users u WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```

### When EXISTS Wins

```sql
-- Complex correlation with multiple conditions
SELECT u.* FROM users u
WHERE EXISTS (
    SELECT 1 FROM orders o
    JOIN order_items oi ON o.id = oi.order_id
    JOIN products p ON oi.product_id = p.id
    WHERE o.user_id = u.id
        AND p.category = 'Laptops'
        AND o.status = 'delivered'
        AND o.created_at >= '2024-01-01'
);
-- Harder to express as clean JOIN
```

---

## Advanced: ANY / ALL / SOME

```sql
-- ANY = true if ANY row matches (same as SOME)
-- Price greater than ANY laptop price
WHERE price > ANY (SELECT price FROM products WHERE category = 'Laptops')
-- Equivalent: price > (SELECT MIN(price) FROM products WHERE category = 'Laptops')

-- ALL = true if ALL rows match
-- Price greater than ALL laptop prices
WHERE price > ALL (SELECT price FROM products WHERE category = 'Laptops')
-- Equivalent: price > (SELECT MAX(price) FROM products WHERE category = 'Laptops')

-- Practical: Find orders larger than 2x user's average
SELECT * FROM orders o1
WHERE total > ALL (
    SELECT AVG(total) * 2 FROM orders o2 WHERE o2.user_id = o1.user_id
);
```
